# Создание строки из формы v2

Дата: 3 ноября 2026 года. Первая часть этапа 5, не весь движок действий.

## Результат

В свойствах формы появилось «После отправки»: проверка либо создание строки
в её таблице. При явном выборе создания подключается одно действие `create_row`
и разрешение выбранным ролям на поля формы. Само добавление компонента прав
не выдаёт. Независимые права таблицы сохраняются при отключении действия;
разрешение вызова этого действия снимается. Общий интерфейс политики впереди.

«Открыть рабочую форму» дожидается сохранения и открывает
`/apps/[appId]/forms/[formId]`. На странице явно указана целевая таблица.
Обязательные поля и ошибки отмечаются рядом с контролами; введённые значения
сохраняются для исправления. После успеха доступны список и «Добавить ещё».
Название формы не дублируется; используются существующие Manrope и sage.

Предпросмотр продолжает вызывать только проверку без записи. Длинный workflow
не сокращается до одного шага: эта реализация принимает только полный контракт
одиночного создания из собственной формы. Для смены уже подключённого поля
сначала отключают действие; новые поля подключаются явно.

## Сервер и права

- Вход доступен только полным редакторам своего пространства, дополнительно
  проверяются роль приложения, доступ к экрану и предкам, разрешение workflow
  и поля `create`. Роли выводятся из проверенной личности и сохранённого приложения.
- Исполняется канонический сохранённый черновик. Клиент не передаёт определение
  действия или доверенную личность. Версия черновика и отпечаток формы защищают
  от сохранения по устаревшим настройкам, полям или версии открытой записи.
- Проверка типов, обязательности, вариантов и связанных строк выполняется
  повторно внутри транзакции. Закрытые начальные значения и связь с открытой
  записью вычисляются сервером. Число 0 и значение false сохраняются.
- Создание использует общее ядро строк: квота, формулы, история изменений,
  предметные проверки и уведомление таблиц после фиксации транзакции.
- Миграция `0025_builder_action_runs` хранит результат по приложению,
  участнику и ключу запроса. Строка и результат фиксируются одной транзакцией.
  Конкурирующие повторы возвращают один ID; другой payload с тем же ключом
  отклоняется. Удаление созданной строки не разрешает повторно создать её
  старым запросом. Связи с приложением и участником очищаются каскадно.
- При неопределённом результате клиент блокирует изменение полей и повторяет
  тот же ключ и значения. После подтверждённого успеха новую отправку можно
  начать только через «Добавить ещё». Последующий отказ из-за изменившихся
  прав не сбрасывает ключ ранее неподтверждённой отправки. Восстановление запроса после полного
  закрытия или перезагрузки страницы пока не реализовано.

## Граница текущей реализации

Это закрытая рабочая форма для автора, доступная за флагом v2. Она исполняет
сохранённый черновик и не публикует приложение. Приложения конечных пользователей
должны исполнять опубликованный снимок; этот слой остаётся следующим этапом.

Чтение записей и вариантов в этой поверхности использует полные права автора
в пространстве. Оно не заявляется изоляцией данных конечных пользователей
по политике приложения. Публикация v2, весь интерфейс ролей, редактирование,
удаление, условия видимости рабочей формы, формы внутри повторяемого списка,
цепочки, журнал цепочек и фоновые действия ещё впереди. Шаг обучения реальному
сохранению не отмечается завершённым через preflight.

## Проверка

- DB-тесты: одна реальная строка и одна история; конкурентный повтор, смена
  payload, ноль и false, закрытые поля, подмена личности, чужое пространство,
  роль, viewer, независимые разрешения, устаревший черновик и контекст,
  автоматическая Relation, отказ длинному workflow, неизменность предпросмотра,
  повтор после удаления результата и атомарный отказ по фактическому лимиту строк.
- Клиент: потеря ответа и тот же ключ повтора, двойное нажатие, новый ключ
  после «Добавить ещё», фокус ошибки, сохранение значений и обновление
  устаревших настроек. Настройка действия проверяется на полном контракте v2.
- Миграции: 26 миграций на отдельной пустой базе, ключ повтора и внешние ключи,
  второй запуск без изменений. Основная локальная база обновлена только
  новой миграцией; история проверена по SHA256.
- Типы и изолированная production-сборка прошли. Основной dev-сервер и его
  `.next` не использовались для production-сборки.
- Браузер: отдельный временный аккаунт, настройка действия, обязательное поле,
  реальное сохранение, строка в списке, ноль, checkbox, число с запятой,
  390 и 320 px без горизонтального переполнения. Данные проверки удалены
  по точной принадлежности тестовому пользователю и пространству. Проверка
  четырёх существующих приложений: все определения совместимы, записей нет.
