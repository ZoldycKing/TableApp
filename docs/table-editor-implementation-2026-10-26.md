# Редактор таблиц по согласованному макету

Дата: 26 октября 2026.

Завершён отдельный этап переноса редактора из макета 19 октября. Использован текущий визуальный стиль TableApp и правила Elaya; остальные дизайн-скиллы не подключались.

## Поведение

- Общая шапка с названием и режимами «Таблицей» / «По записям». Инструменты компактнее; постоянные технические подписи колонок убраны.
- Сетка поддерживает прямоугольный диапазон, Shift + стрелки, перемещение Tab / Shift + Tab, Enter / F2, начало ввода с клавиатуры, копирование и вставку TSV из Excel / Google Sheets.
- Названия вариантов и связанных записей при вставке преобразуются в их ID. Неоднозначные названия и неверные значения отклоняются до записи.
- Новая строка остаётся локальным черновиком. Сохранение явно создаёт запись; отмена не вызывает серверную запись. Ошибка оставляет введённое на экране.
- Если при заполнении черновой строки изменены другие ячейки, правки сохраняются вместе с ней. Это обозначено под сеткой. Отмена черновика отменяет эти несохранённые правки тоже.
- В форме записи изменённые поля сохраняются одним действием. Пояснения полей открываются по вопросительному знаку; множественные связи — в окне с поиском.
- При переключении режимов сохраняются ID выбранной записи, диапазон и прокрутка. Несохранённые правки требуют выбора: сохранить, не сохранять или остаться. Во время запроса переход блокируется.
- Ссылка с выбранной строкой восстанавливает выделение без дополнительной карточки поверх редактора.

### Первый вход и выбранный режим

При первом открытии без указанного режима используется «По записям». Переключение запоминается в этом браузере на год и применяется к следующим таблицам. Сервер учитывает выбор уже при формировании страницы. Прямые ссылки `?mode=grid` / `?mode=records` имеют приоритет, но сами по себе не меняют предпочтение. Ссылки из списка, обзора пространства и сведений о таблице больше не навязывают сетку; настройка полей остаётся прямым переходом в сетку.

После этого изменения прошли 17 проверок переходов и редактора, проверка типов и браузерный сценарий: первый вход → таблица → другая таблица → записи → повторное открытие. Данные аккаунта не записывались.

## Запись данных

`saveTableRowsAction` проверяет права через `authorizeTable`. `commitEditorRows` выполняет весь пакет в общей транзакции `writeRows`, сохраняя проверки бизнес-операций, квот, историю и связанные расчёты.

Сервер проверяет поля, типы, доступность связанных записей и исходные значения изменяемых ячеек. Конфликт в одной строке откатывает весь пакет. Стабильный ID новой строки позволяет безопасно повторить запрос после потерянного ответа без дублирования записи.

Границы: до 500 строк и 5 000 изменяемых ячеек в одном пакете. Новая строка создаётся по одной, как в исходном макете. Вставка за пределы имеющихся строк не создаёт дополнительные строки автоматически. Формулы и другие вычисляемые поля доступны для просмотра и копирования, но не для прямой записи.

## Проверка

- Общая регрессия: 186 файлов, 1 729 тестов — успешно. После неё отдельно пройдены 6 проверок редактора, включая финальную правку открытия выбранной строки по ссылке.
- `pnpm typecheck` — все пакеты, веб-приложение и скрипты прошли проверку.
- Проверки Postgres используют отдельное временное пространство и проверяют откат диапазона, конфликты, повторы создания, вычисляемые поля, недоступные связи и отказ для читателя.
- В браузере подтверждены копирование диапазона, Tab, сохранность неверного числа, ввод и отмена черновика, переход к выбранной записи, восстановление диапазона и прокрутки, подсказка поверх формы и прямая ссылка.
- Оба режима проверены на 320, 390, 768 и 1440 px. Горизонтальное переполнение страницы отсутствует; широкая сетка прокручивается внутри своего блока.
- В настоящем аккаунте сохранились 5 таблиц, 25 записей и 1 приложение. Данные, публикация и доступ не менялись.

Снимки и журналы: `docs/audit/table-editor-reference-2026-10-26/`. Общая галерея обновлена: 59 экранов, 117 снимков. В ней теперь показаны настоящий редактор и отдельная форма записи, вместо прежнего режима просмотра таблицы.

Production-сборка и развёртывание в этом этапе не выполнялись. Права сотрудников на отдельные таблицы затем реализованы [отдельным этапом](table-access-2026-10-26.md). Следующий блок плана — сквозная приёмка пользовательских сценариев и подготовка выпуска.
