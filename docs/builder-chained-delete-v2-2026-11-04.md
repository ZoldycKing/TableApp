# Подтверждаемое удаление внутри цепочек v2

Дата: 4 ноября 2026. Продолжение согласованного рабочего плана конструктора.

## Результат

В общем редакторе шагов доступно «Удалить запись». Автор выбирает таблицу и
текущую строку либо результат предыдущего шага. Подтверждение обязательно,
его нельзя выключить. Поддержаны обычные кнопки, кнопки в списках, itemPress
и формы в рабочем режиме автора и опубликованном приложении. Прежняя
отдельная кнопка удаления карточки сохранила свой контракт и окно.

Окно перечисляет названия всех реально удаляемых записей и таблиц. Оно
подтверждает действие целиком: отмена не сохраняет изменение суммы, запись
журнала или другой предшествующий шаг. Из невыбранных веток записи в окно
не попадают. Кнопки закрытия и отмены блокируются при неизвестном результате;
повтор отправляет прежние значения, ключ и подтверждение.

Настройка удаления выдаёт соответствующим ролям право удаления через общий
механизм явных разрешений. Существующие ограничения «только свои строки»
сохраняются. Автор пространства также выполняет действие по роли приложения;
членство в пространстве само по себе не отменяет ограничения этой роли.

## Транзакционный протокол

1. Канонический источник, выбранная строка и родитель, версия, роль и право
   чтения проверяются так же, как у прочих цепочек.
2. Внутренний savepoint исполняет весь выбранный путь, проверяет права каждого
   удаления и зависимости. Если подтверждения нет, результат выходит через
   специальный ответ, savepoint откатывается целиком. История, связанные
   изменения, usage, результаты, учебные отметки и уведомления не сохраняются.
3. Клиент получает только доступные названия записей и таблиц и отпечаток
   подтверждения. Скрытое первичное поле заменяется общим названием. Новая
   запись, создаваемая в этой цепочке, обозначается отдельно; её случайный ID
   не используется как стабильная идентичность плана.
4. После подтверждения цепочка вычисляется заново под блокировками. Отпечаток
   учитывает описание действия, пользователя, исходную строку, значения формы
   и фактические цели с версиями. Изменившийся план требует нового подтверждения;
   исчезнувшая ветка удаления откатывает действие с предложением обновить данные.
5. Только успешное выполнение получает один результат и журнал. Ошибка
   последующего шага откатывает удаление и предыдущие записи. Эффекты браузера
   возвращаются после успешной транзакции.

В точном повторе запроса удалённые строки используются только для проверки
текущего чтения и поиска прежнего результата. Новое исполнение над удалённой
строкой отклоняется. Для опубликованной формы её канонический путь и аудитория
проверяются до результата, условия видимости — после проверки результата;
поэтому скрывшаяся форма не вызывает ложный отказ при повторе.

Удаление блокируется при зависимых данных, скрытый каскад не выполняется.
Переход к удалённой записи отклоняет всю цепочку. При удалении открытой
карточки без своего перехода выбирается доступный стартовый экран. В списке
сохраняются сообщение и фокус, данные перечитываются. Учебная отметка первого
сохранения не ставится, если та же цепочка удаляет созданную запись.

- Полная регрессия: 257 файлов / 2 191 тест, без ошибок. Первый прогон при
  параллельной проверке типов дал таймаут одного теста команды; отдельно его
  6 проверок прошли, затем полный прогон с двумя workers прошёл целиком.
- После уточнения повторов условно видимой формы: 28 DB-проверок опубликованного
  приложения прошли. Типы всех пакетов/скриптов и финальные типы web проверены.
- Итоговая production-сборка выполнена в отдельной копии исходников, dev .next
  на 3101 не используется для сборки.
- БД: отсутствие сохранённого префикса до подтверждения; подменённое подтверждение;
  кнопка, строка и форма; одновременные повторы после удаления; созданный результат
  как цель удаления; откат после ошибки; зависимые данные; другой пользователь;
  отзыв разрешения; повтор скрывшейся формы; сохранение отдельного удаления.
- UI: обязательное подтверждение в редакторе; окно с конкретным названием;
  отмена без нового запроса; исходные значения формы; заблокированные поля;
  тот же ключ после неизвестного ответа; рабочий режим автора; возврат фокуса.
- Браузер: настройка шага, отказ без права удаления, подтверждение автора,
  отмена без сохранения суммы, запуск клавиатурой, публикация и отдельный участник.
  Окно проверено на 320 × 740: горизонтального переполнения нет.
- Проверочное пространство удалено после сверки: один успешный и один
  отклонённый авторский запуск, один успешный публичный, ровно четыре изменения
  (два изменения суммы и два удаления), чужая строка сохранена. Отмены
  не добавили истории или результатов. После очистки: 4 приложения, 2 старых

## Границы

Обычное удаление не выполняет каскады учётных сценариев. Нельзя открыть
удалённую запись следующим переходом; автор выбирает другой экран.
События открытия экрана, расширенные компоненты, оформление, автоматизации,
группировка и оптимизация больших выборок не включены в этот срез.
