# Галерея и файлы v2

5 ноября 2026 года. Продолжение [общего плана](no-code-builder-implementation.md).

## Результат

В библиотеке конструктора появились «Галерея» и «Файлы». Автор выбирает поле
записи, поле открытой карточки или свои ссылки, добавляет подпись. Для галереи
доступны 2–4 фотографии в ряду на компьютере; на узком экране — не больше двух.
Панель показывает один выбор источника без дублирующего редактора значения.

Фотографии открываются крупно в окне поверх приложения. Есть кнопки следующего
и предыдущего фото, стрелки клавиатуры, счётчик и ссылка на оригинал. Escape
закрывает окно с возвратом фокуса к исходной фотографии. Изображение сохраняет
пропорции и помещается в окно на 320 px. Превью загружаются лениво, сначала
показываются 12 фотографий; остальные раскрываются порциями. Обрабатываются
первые 100 элементов источника. Ошибка загрузки показывает «Фото недоступно».

Список файлов показывает название, тип и известный размер. Вложения TableApp
скачиваются с именем файла, внешние ссылки открываются отдельно. Пустые состояния
для автора содержат следующий шаг настройки, для пользователя — короткое сообщение.
Все элементы используют токены темы приложения.

Поддерживаются массивы вложений внутренних полей `image` и `attachment`, а также
ссылки из `url`, `text`, `long_text` и собственные ссылки по одной на строку.
Небезопасные схемы URL и пути с обходом каталогов отбрасываются, повторы убираются.
При автоматическом создании карточки поле фотографий получает галерею, поле
вложений — список файлов. Уже существующий элемент «Изображение» также понимает
вложение из поля, а не только строковую ссылку. Старые карточки не переписываются.

## Доступ к файлам

Рабочее приложение передаёт контекст `v2App` в ссылке на хранилище. Сервер заново
читает опубликованное описание и текущего пользователя, проверяет пространство,
доступный экран, поле вложения и конкретную живую запись. Ключ должен по-прежнему
находиться в значении этого поля. Скрытое поле, чужая строка, удалённая запись,
отозванный доступ, снятая публикация и неподвязанный файл не выдают содержимое.

При явном контексте приложения нет обхода через одновременно открытую сессию
владельца кабинета. Идентификатор файла сам по себе не даёт разрешения. Файлы
переписки исключены из этого пути; прежняя выдача для кабинета и legacy приложений
сохранена. Ответ использует существующие private/no-store, nosniff и sandbox CSP;
документы отдаются вложением. Новых разрешений при добавлении компонента нет.

## Проверки

- Общая регрессия: **267 файлов / 2 251 тест**, все пройдены. Журнал:
  `.tmp/builder-v23/full-tests-accepted.log`.
- Новые UI-проверки: 7 сценариев парсинга, клавиатуры, фокуса, ошибок, порционной
  загрузки, настроек и автоматической карточки. 4 проверки БД покрывают выдачу
  файлов и отказы по строке, полю, актуальной связи и текущему доступу.
  Контракты проверяют тип источника, контекст, число колонок и старые определения.
- Полная проверка типов пакетов и скриптов пройдена. Финальная production-сборка
  с последней мобильной правкой прошла в `.tmp/builder-v23/build-20261105`,
  отдельно от работающего dev-сервера. Журнал: `.tmp/builder-v23/build-final.log`.
- В старом тесте действий исправлены только данные фикстуры: случайный ID строки
  использовался как дробная позиция и иногда давал недопустимую позицию. Теперь
  тест получает следующую позицию штатным `positionBetween`. Движок записи не менялся.
- В браузере проверены источник галереи, смена 3 → 4 колонок, сохранение и
  публикация; сотрудник с одной доступной записью; реальные изображения из MinIO,
  скачивание и содержимое TXT; отказы для скрытого и чужого файла; просмотр фото,
  клавиатура и возврат фокуса; ширины 390 и 320 px без горизонтального переполнения.
- В проверочной роли не было действия перехода из списка в карточку. Попытку
  дополнить разрешение этой временной роли отклонила автоматическая проверка;
  права не менялись. Для проверки медиа использована прямая ссылка на уже
  разрешённую карточку. Нажатие строки списка этой фикстурой не проверено.
- Временное пространство удалено вместе с восемью объектами хранилища и тестовыми
  сессиями. До удаления: две строки, обе с версией 0. Сохранённые приложения
  совместимы: 4 приложения, 2 legacy и 3 определения v2, 0 отклонений; миграции
  31/31 совпадают. Рабочие пользовательские данные не менялись.

## Границы и следующий шаг

Срез закрывает отображение фотографий и выдачу файлов. Загрузка новых вложений
через формы v2 пока не подключена; существующая загрузка в редакторе таблиц
сохраняется. Также не добавлены встроенный просмотр документов, загрузка видео,
собственный логотип и разворачивание вложенных массивов lookup в галерее.

Следующий срез — выбор и загрузка фото/документов в формах создания и изменения
с проверкой прав, ошибок, повторов и привязки файла к сохранённой записи.
Этап 7 остаётся частичным. События открытия экранов, автоматизации, группировка,
оптимизация больших выборок, бизнес-адаптеры и общая приёмка остаются в плане.
