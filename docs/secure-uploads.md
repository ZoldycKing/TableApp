# Безопасные загрузки файлов

Загрузки пользователей (переписка по обращениям, поля вложений, формы конструктора)
проходят общую проверку типа, размера, перекодирование изображений и опциональное
сканирование ClamAV.

## Что принимается

| Тип | Как определяется |
| --- | --- |
| PNG, JPEG, WebP, GIF | Сигнатура содержимого; перед сохранением файл перекодируется (EXIF удаляется) |
| HEIC / HEIF | Сигнатура `ftyp`; при поддержке libvips перекодируется в JPEG, иначе отказ |
| PDF | Сигнатура `%PDF` |
| DOCX / XLSX | ZIP-контейнер OOXML без макросов |
| TXT / CSV | Текстовое содержимое без нулевых байтов |

Отклоняются: исполняемые файлы, скрипты, HTML, SVG, архивы, Office с макросами
(DOCM, XLSM и т.п.), неизвестные бинарные форматы.

Лимит размера задаётся `UPLOAD_MAX_BYTES` (по умолчанию 15 МБ). Частота загрузок
одного пользователя — `UPLOAD_RATE_LIMIT` (по умолчанию 120 в минуту; для вложений
переписки дополнительно действует лимит 20 в минуту).

## Хранение и выдача

- Имя объекта в S3/MinIO случайное: `{workspaceId}/{32 hex}[.ext]`.
- Файлы не лежат в web-root приложения и не исполняются сервером.
- Скачивание: `Content-Disposition: attachment`, кроме перекодированных изображений
  (`inline`), плюс `X-Content-Type-Options: nosniff`, ограничивающий CSP и верный
  `Content-Type`.
- Доступ проверяется на каждый запрос: участник пространства, посетитель приложения
  или участник переписки — по тем же правилам, что и для записи/диалога.

Опциональный отдельный домен раздачи (выключен по умолчанию):

```env
NEXT_PUBLIC_FILES_ORIGIN=https://files.example.com
FILES_PUBLIC_ORIGIN=https://files.example.com
```

На этом хосте должен обслуживаться тот же `GET /api/files/...` с теми же проверками
доступа. Пока переменные пусты, ссылки остаются на основном `APP_URL`.

## Антивирус (ClamAV)

Если задан `CLAMAV_HOST` (например `127.0.0.1:3310`) или `CLAMAV_SOCKET`, каждый
файл после записи в хранилище сканируется через `clamd` (INSTREAM). Иначе
сканирование пропускается, в лог один раз пишется предупреждение, загрузка не
падает.

Состояния вложения:

| UI | `state` / `scan_status` | Скачивание |
| --- | --- | --- |
| Проверяется | `scanning` / `pending` | Нет |
| (доступен) | `ready` / `clean` или `skipped` | Да |
| Файл заблокирован | `blocked` / `infected` | Нет, объект удалён |

Локально:

```sh
docker compose up -d clamav
# в .env:
CLAMAV_HOST=127.0.0.1:3310
```

Первый старт контейнера долго обновляет базы сигнатур. Проверка: `echo PING | nc 127.0.0.1 3310` → `PONG`.

CI Verify поднимает только Postgres и MinIO; без ClamAV тесты мокают `clamd` и
проверяют ветки clean / infected / skipped.
