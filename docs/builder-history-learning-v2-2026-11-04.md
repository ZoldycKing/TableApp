# Журнал действий и обучение публикации — 4 ноября 2026

В новом конструкторе автор может посмотреть действия пользователей рабочего
приложения. Первые шаги продолжаются настройкой доступа и публикацией.
Оформление использует существующие Manrope, зелёные акценты и окна поверх редактора.

## Журнал

Кнопка «История действий» находится рядом с отменой изменений в заголовке.
По умолчанию открывается «В приложении». Для каждого запуска показаны действие,
имя или почта пользователя, время и результат. «Посмотреть шаги» показывает
выполненные, пропущенные, отменённые и ошибочные шаги. Ошибка не предлагает
автоматически повторять записывающее действие из журнала.

«Мои действия» содержит только собственные запуски автора в закрытом рабочем
режиме. Предпросмотр не записывает данные и не создаёт запуск. Это реальные
действия, поэтому вкладка не называется «Проверки».

Опубликованный журнал читается только полным редактором этого пространства
и приложения. Пользователи приложения, наблюдатели, участники с доступом
только к отдельным таблицам и другое пространство получают отказ. Почта
участника берётся из профиля именно этого приложения. Клиенту не передаются
внутренние запросы, ключи повторов и конфигурации цепочек.

Пагинация по десять запусков использует шифрованный курсор, привязанный
к приложению, пространству, автору и вкладке. При равном времени порядок
стабилен по ID. Чужой или устаревший курсор предлагает обновить список.
При переключении вкладки запоздалый ответ предыдущей загрузки отбрасывается.

## Четыре доступных шага обучения

1. Настроить поле или вид списка. Выполнение подтверждает сохранение черновика.
2. Открыть настоящую карточку. Выполнение подтверждает серверное чтение записи.
3. Проверить доступ. Кнопка открывает существующее окно «Доступ»; после
   «Сохранить доступ» завершается автосохранение и сервер проверяет ту же ревизию.
4. Опубликовать приложение. Кнопка открывает подтверждение. Прогресс обновляется
   в той же транзакции, которая сохраняет опубликованный снимок.

Открытие, отмена и ошибка публикации не считаются выполнением. Проверка
несохранённого либо устаревшего доступа отклоняется. Проверка доступа не выдаёт
новых прав сама по себе. Если результат записи прогресса потерян, повторяется
подтверждение той же ревизии.

Каждый шаг можно пропустить, продолжить позже или вернуть из пропущенных.
Пауза сохраняется при конкурентном подтверждении шага. Сохранённые первые
два шага не сбрасываются. Удалённый список не мешает пройти доступ и публикацию,
если работа со списком уже завершена либо пропущена.

Миграция `0029_builder_learning_publication` добавляет четыре булевых столбца
и проверку несовместимых done/skipped. Старые флаги, пауза и определения
приложений не переписываются. Формат прогресса расширен дополнительными полями.

Помощь содержит только объяснение текущего шага и открывается поверх редактора.
Отдельный учебный шаг первого сохранения записи из формы остаётся в очереди;
выполнение настройки списка не выдаётся за создание строки.

## Проверки

- Полная регрессия: **254 файла, 2 138 тестов**, все пройдены. После уточнения
  названия вкладки отдельно повторены три проверки журнала.
- Проверка типов проекта и изолированная production-сборка пройдены.
- Smoke миграций на пустой БД и повтор без изменений: **30 миграций, 40 таблиц**.
  Проверены новые столбцы прогресса и ограничение статусов.
- БД: границы доступа к журналу, два пользователя одного приложения, чужое
  приложение и автор, подмена вкладки и курсора, равное время записей, ошибка
  с откатом и отдельная история автора.
- Обучение: несохранённый и неподготовленный доступ, конкурентная пауза,
  пропуск/возврат, ошибка публикации, повтор успешной публикации без повторного
  обновления прогресса и изоляция участников.
- Интерфейс: запоздалые ответы журнала, повтор загрузки после устаревшего
  курсора, открытие публикации без автоматического выполнения, отмена окна,
  повтор подтверждения доступа и честное отображение пропущенного шага.

В браузере на отдельном временном аккаунте пройдены все четыре шага. После
обновления страницы они остались выполненными. Настоящий пользователь
опубликованного приложения запустил цепочку с поздней проверкой бюджета:
изменение отменилось. После сохранения подходящего бюджета следующий запуск
прошёл. Автор увидел в журнале один ошибочный и два успешных запуска, причину
ошибки и отменённый шаг. В таблице остались исходные две строки, результатов
успешных запросов — два, участников пространства — один автор.

Проверены компьютер и 320 px: переполнения нет, длинная почта переносится,
обучение и шаги читаются. Escape закрывает журнал и возвращает фокус на кнопку
«История действий». При проверке найдено раннее нативное отправление формы
входа до загрузки обработчиков. Для нового опубликованного приложения поля
и отправка теперь включаются после готовности интерфейса; старые сценарии
входа проверены отдельно.

Временное пространство и аккаунт удалены по точным ID с проверкой имени
и владельца. Вкладки закрыты, размер браузера восстановлен. Проверка четырёх
существующих приложений: 2 legacy- и 3 v2-определения совместимы, отклонённых
нет, записей в них не выполнялось. Локальная история миграций совпадает:
30 из 30, ожидающих нет.
