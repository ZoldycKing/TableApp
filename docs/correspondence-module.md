# Переписка (CorrespondenceModule)

Модуль клиентской переписки по записи: сообщения, вложения и внутренние заметки сотрудников. Клиент видит только публичные сообщения своих обращений.

## Где появляется

- В **карточке записи** (экран подробностей) — под содержимым записи.
- В разделе **«Чат»** (клиент) / **«Сообщения»** (сотрудники) внутри опубликованного приложения, и в общем `/messages` владельца.

## Как включить

В настройках приложения («Возможности») кнопка **«Включить переписку»**. Подпись: «В карточке записи и в разделе „Сообщения“». Изменение пишется в черновик; клиенты увидят его после публикации.

Отключение не удаляет существующие диалоги: новые треды не создаются, уже начатые остаются доступны для чтения и ответа (в UI — `configured={false}`, панель скрыта только если треда ещё нет).

## Требования

1. Клиентский сценарий с **карточкой обращения** (detail-экран с ролью `client`).
2. Поле **почты клиента** на этой таблице (через `customer` / `booking` или App V2 `service` / `support`).

Без клиентской карточки сервер отвечает: «Для переписки нужна клиентская карточка записи…». Без поля почты / сценария: «Для переписки нужно поле почты клиента…».

Шаблоны **«Сервисный центр»** и **«Обращения и поддержка»** устанавливаются с `communications.enabled: true` и валидным клиентским кабинетом.

## API компонента

```tsx
<CorrespondenceModule
  slug={app.slug}
  tableId={screen.tableId}
  rowId={row.id}
  configured={Boolean(app.communications?.enabled)}
  business={false}          // true только в контуре владельца /messages
  showContext={false}       // false внутри карточки — без дублирующего заголовка
/>
```

Опционально для шотов: `fixture`, `fixtureFiles`, `fixtureAlert` — без сети.

Сервер: `readConversation` / `sendConversation` / заметки через `conversation-actions` → `lib/conversations.ts`. Права не ослабляются: клиент читает только свои записи по подтверждённой почте; заметки запрашиваются только для staff.
