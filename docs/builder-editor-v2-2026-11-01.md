# Редактор приложений v2 — 1 ноября 2026

Реализована редакторская часть этапа 3 из
[плана конструктора](no-code-builder-implementation.md). Это серверный черновик
приложения, отдельный от синтетической лаборатории `/builder-lab`.

## Что работает

- Создание приложения с пустым стартовым экраном без обязательной таблицы:
  `/apps/new?builder=1`. Черновик появляется в обычном списке приложений.
- Свои экраны: названия, иконки, порядок, показ в меню, стартовый экран,
  контекст выбранной записи и удаление с подтверждением.
- Библиотека элементов: заголовок, текст, изображение, разделитель, группа,
  колонки, коллекция, показатель, кнопка, форма и поля внутри формы.
- Согласованный выбор элемента на экране, в дереве и в свойствах. Перестановка,
  выбор родителя, перетаскивание в дереве, копирование поддерева, отмена и повтор.
- Выбор внутренних таблиц по метаданным. У коллекции различаются список,
  карточки и таблица; у показателя задаются операция и числовое поле.
- Автоматическое сохранение с задержкой 800 мс и последовательной очередью.
  Правки во время запроса сохраняются следующими, против полученной ревизии.
  Изменения переживают обновление страницы и повторное открытие из списка.
- Защита двух вкладок: отличающаяся устаревшая версия получает конфликт,
  её локальные правки сохраняются на экране. Серверная версия загружается
  только после отдельного подтверждения. Ошибка загрузки остаётся внутри окна.
- Повтор сохранения при ошибке соединения и предупреждение браузера при
  закрытии страницы с несохранёнными правками.
- Один `AppV2Renderer` для редактора и отдельного защищённого предпросмотра.
  Формы и действия в просмотре не записывают данные.
- На узком экране дерево, приложение и свойства переключаются панелями.
  Колонки и карточки перестраиваются по ширине самого приложения.

## Границы этого этапа

Редактор получает **только метаданные** внутренних таблиц, без строк. Макеты
коллекций и пустые показатели обозначают место будущих данных. Серверные
запросы, отбор, вычисляемые значения и порционная загрузка относятся к этапу 4;
запись форм и выполнение действий — к этапам 5–6. Публикация v2 пока выключена.

Общий renderer уже подключён к двум режимам просмотра. Его совпадение с
публичным опубликованным приложением ещё не принято: публичный runtime будет
подключён после слоя данных и действий. Не следует считать этот этап готовой
заменой всех возможностей Glide или готовым публичным приложением.

Старые приложения продолжают открываться в прежнем редакторе. Автоматического
переноса их конфигурации и рабочих данных не было. Старое действие сохранения
отклоняет v2, новое — v1; прежняя публикация не принимает новый формат.

Новый путь включён в development. В production создание и изменение v2
требуют `TABLEAPP_BUILDER_V2=1`; без флага существующий черновик доступен
авторизованному участнику только для просмотра. Флаг не включает публикацию.
Файл окружения и развёрнутое окружение не менялись.

## Серверные ограничения

Сохранение повторно проверяет членство, права редактирования, принадлежность
приложения пространству, неизменность адреса и идентификаторов, актуальную
структуру таблиц и семантику ссылок. Размещение элемента не добавляет разрешений
на чтение или изменение данных. Просматривающие и участники с доступом только
к отдельным таблицам не получают возможность сохранять конфигурацию.

Ревизия — канонический отпечаток определения; сравнение и запись происходят
под блокировкой строки приложения. Повтор того же уже сохранённого снимка
идемпотентен. Создание защищено повторяемым идентификатором запроса и блокировкой
адресов. Контрольная точка конфигурации создаётся перед первым изменением,
далее не чаще одного раза за пять минут. Интерфейс восстановления v2 пока не
добавлен; локальные отмена и повтор уже доступны.

## Проверки

- `pnpm typecheck`: все пакеты, web и служебные скрипты прошли.
- `pnpm exec vitest run --maxWorkers=4`: **221 файл, 1981 тест**, все прошли.
  Новые проверки охватывают БД и авторизацию, конфликты и очередь сохранения,
  граф и копирование форм, общий renderer и запрет записей из просмотра.
- Production-сборка Next 16.3.5 выполнена в отдельной копии исходников.
  Работающая `.next` сервера на 3101 не использовалась для сборки.
- В Chrome через Playwright CLI проверены создание, выбор источника,
  изменение свойств, копирование, отмена и повтор, создание второго экрана
  с формой, сохранение и повторное открытие, отдельный просмотр и список
  приложений. Конфликт воспроизведён в двух настоящих вкладках; Escape
  закрывает окно без потери правок, явная загрузка заменяет их сохранённой версией.
- Проверены 1440×1000, 390×844 и 320×780; при 320 px документ не выходит
  за ширину экрана. Это эмуляция размеров, не проверка физических телефонов.
- Ошибки локального Agentation на порту 4747 относятся к отключённой панели
  обратной связи, а не к сохранению приложения.

Браузерный сценарий выполнялся в отдельном временном аккаунте с двумя пустыми
таблицами. После проверки этот аккаунт, его приложение и метаданные удалены.
Рабочие аккаунты для записи не использовались.
После очистки повторно проверены сохранённые определения: одно прежнее
приложение, два определения, совместимость подтверждена; проверка не делала записей.
