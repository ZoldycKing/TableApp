# MVP: базовый функционал

Позиционирование: симбиоз Airtable и Glide. Внизу — совместная база данных с
представлениями, наверху — конструктор мобильных приложений поверх неё.
Редактор базы и конструктор — десктоп. Приложение конечного пользователя — mobile-first.

## Ключевая идея архитектуры

Представление = { таблица, фильтры, сортировка, группировка, видимые поля, порядок строк }.

Один этот объект рендерится восемью способами:
- в редакторе базы: Грид, Канбан, Календарь, Галерея
- в приложении: Список, Плитка, Карточка, Форма

Движок фильтрации, вычисления формул и применения прав пишется один раз
и обслуживает обе половины продукта.

## Два контура пользователей

- Участники команды — работают в базе, редактируют данные, занимают платные места.
- Конечные пользователи — работают в опубликованном приложении, бесплатны и безлимитны.

Разные способы входа, разные права, разная тарификация.

## 1. Аккаунт и команда

- Вход по magic link на email.
- Воркспейс с приглашением участников по email.
- Три роли: Владелец, Редактор, Зритель. Уровень воркспейса, не таблицы.

## 2. База

### Таблицы
- Создание пустой таблицы или импорт XLSX/CSV с автоопределением типов. В книге Excel выбираются один или несколько листов, каждый со своими настройками колонок и своей таблицей-приёмником.
- Грид: колонки, строки, типы, изменение ширины и порядка, закрепление первой колонки.
- Фильтры, сортировка, группировка, поиск.
- Экспорт в CSV.
- Совместная работа: изменения прилетают другим участникам сами.
  Курсоров и присутствия в MVP нет.

  **Решение изменено: вместо WebSocket — SSE.** Поток событий односторонний:
  сервер говорит «таблица изменилась», браузер перечитывает её обычным путём,
  со всеми проверками прав. Обратный канал уже есть — серверные действия.
  Сокет потребовал бы своего сервера с обработкой upgrade, а приложение живёт
  на маршрутах-обработчиках Next; выгоды от двунаправленности при таком
  обмене нет. Это не опрос: соединение одно и держится, пока открыта вкладка.
  Подробности и границы — `apps/web/src/lib/live.ts`.
- Журнал изменений пишется с первого дня, UI истории версий — позже.

### Типы полей
Базовые: Текст, Длинный текст, Число (обычное/деньги/процент), Дата, Дата и время,
Переключатель, Одиночный выбор, Множественный выбор, Вложения, Изображение,
Email, Телефон, Ссылка, Участник.

Связи: Связь с другой таблицей.

Вычисляемые: Формула, Lookup, Rollup (SUM, COUNT, MIN, MAX, AVG), Количество связей.

Системные: ID строки, Создано (когда/кем), Изменено (когда/кем).

Режем: гео, штрихкод, подпись, рейтинг, длительность, AI-поля.

### Формулы
Область видимости — текущая строка плюс значения через Lookup и Rollup.
Набор функций (~25): арифметика и сравнения, IF/AND/OR/NOT,
CONCAT LEN LEFT RIGHT MID UPPER LOWER TRIM REPLACE,
ROUND ABS MIN MAX, TODAY NOW DATEADD DATEDIFF FORMAT_DATE.
Ссылка на поле синтаксисом {Имя поля}, резолвится в стабильный id при сохранении.

### Представления в редакторе
- Грид — основной режим.
- Канбан — группировка по полю одиночного выбора или связи, перетаскивание карточек.
- Календарь — по полю даты, месяц и неделя.
- Галерея — карточки с изображением.

Каждое представление хранит свои фильтры, сортировку и набор видимых полей.

## 3. Приложение

- Приложение = экраны + нижняя навигация на 2-5 вкладок.
- Экраны: Список, Плитка, Карточка (одна строка), Форма (создание или редактирование).
  Источник экрана — представление базы, со своими доп. фильтрами.
- Компоненты (10): Заголовок, Текст, Изображение, Поле, Кнопка, Разделитель,
  Связанный список, Галерея, Поле формы, Карточка.
- Привязка компонента к полю текущей строки.
- Оформление: акцентный цвет, логотип, иконка, название.
- Живое превью в мобильной рамке.

### Действия
Открыть экран, Создать строку, Изменить строку, Удалить строку (с подтверждением),
Открыть ссылку, Позвонить, Написать на email, Назад.

## 4. Публикация и доступ

- Ссылка вида app.домен.ru/a/<slug>.
- Режимы: публичный по ссылке / вход по email-коду / доступ по списку email.
- PWA: манифест, иконка, добавление на главный экран. Офлайн только на чтение.
- Row-level security для конечных пользователей: правило
  "видит строки, где поле X равно его email". Применяется на сервере при отдаче данных.

## 5. Биллинг

**Решение изменено: платит пространство, а не место редактора.** Считается
объём данных — строки, опубликованные приложения, таблицы и файлы; количество
людей на цену не влияет вовсе. Платить за каждого сотрудника — ровно то,
из-за чего малый бизнес уходит от зарубежных сервисов. Тарифы и потолки
лежат в `packages/schema/src/plans.ts`, они же показываются на сайте
и в кабинете.

- Бесплатный тариф: без ограничения по времени и без карты. Водяного знака
  в рантайме нет — решение отменено, он не продаёт, а портит приложение клиента.
- Платные тарифы: оплата подписки вперёд, 30 суток за месяц, **без
  автопродления**. Дни при досрочной оплате складываются.
- Кончился срок — пространство возвращается на бесплатный тариф, данные
  и опубликованные приложения остаются; ограничивается только рост.
- Провайдер-кандидат — ЮKassa. Наша половина готова и проверена
  в контуре без денег; настоящая интеграция требует договора и ключей.
  Подробности и порядок подключения — `docs/payments.md`.

## Не входит в MVP

Автоматизации, триггеры и вебхуки. Комментарии к строкам. UI истории версий.
Курсоры и присутствие. Права на уровне таблиц и полей. Кастомные домены.
Офлайн-запись. Интеграции с 1С/Битрикс24/amoCRM. Шаблоны приложений и баз.
Публичный API. Многоязычность.

## Порядок сборки

1. База: таблицы, поля, грид, импорт. Пригодна сама по себе.
2. Движок представлений: фильтры, сортировка, группировка. Затем канбан, календарь, галерея.
3. Формулы, связи, Lookup и Rollup.
4. Рантайм приложения поверх готового движка представлений.
5. Публикация, доступ конечных пользователей, биллинг.

Публичный запуск — только после шага 4: без приложений продукт неотличим
от очередного клона Airtable.
