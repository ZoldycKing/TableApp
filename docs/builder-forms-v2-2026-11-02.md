# Формы конструктора v2

Дата: 2 ноября 2026 года. Часть этапа 4
[плана реализации](no-code-builder-implementation.md).

## Результат

В карточку или обычный экран можно добавить форму из внутренней таблицы. Форма
получает несколько подходящих полей, главное поле обязательно по умолчанию.
«Добавить поле» открывает выбор ещё не использованных колонок. Поля можно
переименовывать, менять их обязательность, переставлять, удалять и дублировать
вместе с формой. Вычисляемые поля не предлагаются для ввода.

Свойства поля позволяют задать начальное значение, взять данные вошедшего автора,
значение поля открытой записи или связь с открытой записью. Для одной однозначной
Relation к таблице карточки новая форма сама подставляет связь и делает её
недоступной для случайной замены. Это универсальный механизм: заказ клиента,
задача проекта и другие связанные записи используют один контракт.

В предпросмотре поля доступны для заполнения. Поддержаны текст, длинный текст,
число с десятичной запятой, почта, телефон, URL, дата, дата со временем, отметка,
один/несколько вариантов и Relation. Для редактируемой Relation есть поиск
по обычному главному полю связанной таблицы и порции по 30 записей. Начальные
значения из настроек таблицы применяются сервером, включая вариант по умолчанию
и дату. Автоматическая связь показывает название записи вместо технического ID.

«Проверить форму» проверяет значения на сервере. Неверные поля получают отдельные
сообщения, фокус переходит к первой ошибке, остальные значения остаются для
исправления. Успех прямо говорит, что проверочная запись не сохранена в таблицу.
При смене открытой записи форма не показывает данные или запоздавшие ответы
предыдущей. При изменении настроек или версии открытой записи предлагается
обновить форму. Режим edit загружает текущие значения своей записи для проверки.

## Сервер и контракты

В binding v2 добавлен `record_ids`: таблица и источник записи (строка, открытая
карточка, результат шага). Resolver проверяет таблицу и возвращает массив Relation.
Схема проверяет таблицу назначения и тип начального значения. В input добавлен
необязательный readOnly, в form необязательная надпись на кнопке. Существующие
определения без этих свойств читаются без добавления значений по умолчанию.

Endpoint доступен проверенному автору с полным доступом к пространству. Он
проверяет владельца приложения, каталог и принадлежность формы экрану. Открытая
запись читается заново по ID нужной таблицы, данные пользователя берутся из
сессии. Поля с запретом редактирования пересчитываются сервером. Передать их
в пользовательском payload, подменить актёра, таблицу, вычисляемое или постороннее
поле нельзя. Проверяются обязательность, тип, варианты выбора, URL/почта, дата,
кардинальность Relation и точные доступные строки таблицы назначения.

Подготовка и проверка работают в read-only repeatable-read транзакциях. Модуль
форм не импортирует функции записи. Даже если у формы уже настроено submit
с цепочкой действий, preflight её не исполняет.

## Границы

Работает авторская проверка формы. Сохранение конечным пользователем,
исполнение submit, публикация v2, политика приложения, разрешения на изменение,
защита повторов и бизнес-проверки записи подключаются в следующих частях 4–6.
Preflight не означает, что уже проверены складские операции, расписание,
лимиты тарифа или бизнес-действия при реальном сохранении.

Файлы, изображения и участники пока не предлагаются новыми формами. Условная
видимость элементов формы пока отклоняется понятным сообщением, чтобы скрытое
обязательное поле не создавало непонятную ошибку. Поиск Relation с вычисляемым
главным полем потребует отдельной реализации. Эти ограничения не скрываются
под успешной проверкой.

## Проверки

- Полная регрессия: **229 файлов, 2015 тестов** прошли. После доработки выбора
  полей: **13 файлов, 97 целевых тестов** прошли.
- Все пакеты, web и служебные скрипты прошли `pnpm typecheck`.
- Production-сборка прошла в отдельной копии исходников. Рабочая `.next` сервера
  3101 не использовалась для сборки.
- Проверены типизированная Relation, неправильная таблица, начальные значения,
  обязательность, ноль и false, варианты выбора, дата, подмена readOnly/актора/
  вычисляемого поля, чужие и удалённые записи, устаревшее состояние, edit-форма,
  права читателя, отсутствие изменений строк, истории и draft из preflight.
- Проверены ввод дробной суммы с запятой, нормализация даты, отображение названия
  связанной записи, фокус ошибки, сохранение ввода для исправления, отсутствие
  выполнения submit и защита от запоздавшего ответа старой формы.
- В браузере: добавить форму заказа в карточку клиента → добавить выбранные
  поля → задать автоматическую почту → открыть клиента → проверить обязательное
  поле → заполнить сумму, статус и дату → проверить форму → открыть другого клиента.
  Новая форма получила другого клиента и пустые пользовательские значения.
- Отдельный просмотр, возврат в редактор, размеры 1440, 390 и 320 px, включая
  свойства поля на узком экране, проверены без горизонтальной прокрутки документа.
  Проверка размеров выполнена в браузере, не на физических телефонах.

После браузерных проверок в тестовой таблице заказов осталось **0 строк**.
Созданные мной аккаунт и пространство удалены. Реальные приложения и таблицы
пользователя не изменялись.
