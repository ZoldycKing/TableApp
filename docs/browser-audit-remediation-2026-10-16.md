## Замечания без отдельной реализации

- **A08:** сложность первого запуска подтверждена как наблюдение интерфейса, но влияние на пользователей не измерено. Полный редизайн модульного конструктора ранее отложен пользователем; этот набор исправлений не вводит новый мастер и не заявляет решение проблемы понятности первого запуска.
- **A09:** при повторной установке «Сервисного центра» в новом тестовом бизнесе воспроизведена подсказка со ссылкой на отсутствующий раздел «Доступ». Она заменена прямой ссылкой на настройки приложения, где задаются почты сотрудников и рабочие роли. Уровни прав команды и приложения по-прежнему различаются; новый мастер назначения не добавлен.
- **A15:** гипотеза об отсутствии пояснения, где придёт ответ на общий вопрос, опровергнута для проверенного сценария: пояснение уже есть, ответ пришёл в «Сообщения». Email/push-уведомления не добавлялись.

## Дополнительные исправления при приёмке наборов

- **Отказ и отмена:** после клиентского отказа от ремонта или отмены выбирается история, чтобы сохранённая запись не выглядела исчезнувшей из пустого активного списка. Две интеграционные регрессии и повторный отказ в браузере прошли.
- **Рабочая переписка:** определение сотрудника для текста и кнопки вопроса больше не зависит от наличия модулей. Переход из доступной рабочей карточки не требует отсутствующего в проекции клиентского экрана; каноническая серверная проверка сохранена. 18 регрессий проверяют роли и точную цель перехода. Мастер и курьер проверены в браузере.
- **Вложения:** поздние загрузки и отправки из предыдущего диалога не изменяют новый черновик; отправка ждёт файл, удалённое вложение не возвращается. Сбой второго файла не теряет первый. Клиент может приложить файл к новому сообщению закрытого общего вопроса; подготовка файла не возобновляет диалог и не открывает черновик владельцу или другому клиенту. Закрытые переписки по записям сохраняют прежние ограничения. 50 целевых компонентных и PostgreSQL-тестов прошли.
- **Данные доставки:** новый шаблон показывает курьеру инструкции клиента, способ расчёта и сохранённое фото. `workerReadFields` дополняет только чтение назначенной строки; прав менять комментарий, расчёты, почту и назначение не добавлено. Клиент видит свой комментарий. Тестовая установленная карточка настроена через конструктор; в браузере проверены инструкции и условия расчёта, фото — только автоматической проекцией.
- **Жизненный цикл меню:** один CI-прогон завершился необработанной ошибкой после 1552 успешных тестов: отложенный таймер боковой панели срабатывал после удаления её окружения. Оболочка теперь очищает таймер; вызов очистки дочернего меню не ставит новый после удаления родителя. Три регрессии проверяют ожидающие открытие/закрытие и открытое меню. В трёх существующих UI-тестах следующие действия теперь ждут доступности элементов после завершения `useTransition`, без искусственных задержек и изменения логики приложения.

После этих изменений полный прогон: **159 файлов, 1555 тестов прошли**, без необработанных ошибок; корневая проверка типов и сборка Next.js успешны, `git diff --check` чист. Детали нового сервисного центра, доставки и границ проверки записаны в [матрице приёмки](template-acceptance-2026-10-16.md). Следующий исторический раздел описывает предыдущие прогоны отдельно.

## Проверка результата

Итоговый `pnpm test`: **156 файлов, 1521 тест прошли**. `pnpm typecheck` прошёл для всех пакетов и скриптов. Сборка Next.js прошла через локальный `owner-navigation-preview.mjs build`: этот wrapper задаёт только процессу тестовый `SITE_URL` и console-mail, сохранённый `.env` не меняется. Обычный первый запуск `pnpm build` выявил отсутствие допустимого production `SITE_URL` в локальном окружении; конфигурация production этим не проверена. `git diff --check` не обнаружил ошибок пробелов.

Дополнительные интеграционные регрессии проверяют потерянный ответ после уже сохранённой заявки: правка поля и перезагрузка не меняют ключ повтора и не создают дубль. Черновик переноса сохраняет исходную версию визита; после изменения сотрудником сервер получает старую версию и отклоняет перезапись. Явная загрузка актуальных данных сбрасывает старый ввод и только затем использует новую версию. Старые callback формы не могут вернуть сброшенный черновик.

При независимой проверке перед фиксацией исправлена история браузера после оформления: отправленная форма заменяется списком перед открытием созданной карточки. Интеграционный тест с включённой историей воспроизвёл ошибку до исправления и проверяет возврат кнопкой шапки, Back/Forward браузера и отсутствие повторного создания. После изменения целевой набор `app-shell-audit.test.tsx` прошёл 7/7, web typecheck прошёл; полную проверку новой версии выполняет следующий запуск CI.

Следующая приёмка на новом сервисном центре выявила краткое ложное «Запись недоступна» между созданием строки и обновлением серверных данных. До получения свежего ответа карточка теперь показывает загрузку. Настоящий ответ без доступной строки по-прежнему показывает недоступность; после 15 секунд доступно явное обновление карточки без повторного создания. Целевой интеграционный набор расширен до 9 тестов и прошёл; web typecheck прошёл. Сценарий нового бизнеса и оставшаяся матрица описаны [отдельно](template-acceptance-2026-10-16.md).

2. **Запись на телефоне 390×844:** услуга, дата, время и изменённое имя восстановились после перехода в каталог и полной перезагрузки. После подтверждения открылась конкретная карточка визита.
