# Опубликованное приложение v2 — 3 ноября 2026

Новый конструктор публикует рабочую версию приложения. Пользователь входит
по коду на почту, видит свои разрешённые экраны и данные, сохраняет формы
и запускает кнопки. Членство в пространстве автора ему не требуется.

## Путь автора

1. В «Доступ → Вход» выбрать вход по списку почт или по любой подтверждённой
   почте с заданной ролью. Добавить адреса и роли. Приглашения автоматически
   не отправляются: автор передаёт опубликованную ссылку сам.
2. В «Экраны» отметить разделы для роли. Чистое открытие карточки следует
   доступу к разделу; это не выдаёт разрешения на изменение данных.
3. В «Данные» выбрать таблицу, роль, поля и все записи либо только свои.
   Для своих записей указываются поле владельца и свойство пользователя.
   Чтение без входа — отдельный явный выбор.
4. Действия и разрешённые роли задать в свойствах форм и кнопок.
5. Нажать «Опубликовать». Сначала завершается автосохранение; сервер принимает
   только точную сохранённую ревизию. В окне результата появляется рабочая ссылка.

Правки после публикации остаются в черновике. Перед публикацией проверяются
структура, реальные таблицы и ссылки, поддержка действий и доступность чтения.
Проверяется квота опубликованных приложений. Создаётся версия настроек.

Базовое окно не объединяет разные правила чтения одной роли в более широкое
правило. Они сохраняются без изменений; для замены одним правилом требуется
сначала явно убрать чтение этой роли в выбранной таблице. Права других ролей,
публичное чтение и отдельные разрешения записи сохраняются.

## Исполнение и доступ

Сервер заново получает опубликованное определение и проверенную почту при
каждом запросе. Роли вычисляются из этого снимка, идентификатор пользователя
приложения отдельный для каждого приложения. Данные аккаунта, роли,
определение приложения и цепочка из браузера не принимаются.

В браузер передаются текущий разрешённый экран, безопасная навигация и
разрешённые метаданные. Список приглашённых, политика и тела записывающих
цепочек остаются на сервере. Скрытые поля не возвращаются в строках.

Списки, точная карточка, поиск, сортировка, показатели и варианты связей
используют доступ конечного пользователя. Связанные строки фильтруются до
вычисления. Формула не получает скрытый исходный столбец, Lookup и Rollup —
скрытое целевое поле. Курсор привязан к пользователю, ревизии, экрану,
контекстной записи, поиску и доступным данным.

Первые одновременные запросы одного нового пользователя могут столкнуться
при создании его профиля. Чтение повторяет транзакцию при PostgreSQL 40001,
не превращая этот конфликт в страницу «Недоступно». Существующий профиль
читается без повторного INSERT. Это проверено восемью параллельными запросами.

Почта вне списка получает одинаковый ответ о запросе кода, но письмо, токен
и профиль для неё не создаются. В открытом режиме роль по умолчанию действует
после подтверждения почты. Удаление из опубликованного списка либо новая
публикация проверяются до чтения и до повторного исполнения старого запроса.

## Формы и кнопки

Опубликованные формы и кнопки используют общий движок с режимом автора:
`require`, `branch`, `create_row`, `update_row`, `notify`, `open_screen`.
Проверяются роль, видимость элемента, контекст строки, поля, связи и версия.
Условие и результат шага не получают скрытые данные. Владельца новой строки
и заблокированную связь с родителем назначает сервер.

Цепочка, история изменений, расход квоты и результат запроса сохраняются
атомарно. Ошибка позднего шага откатывает записи и историю. Ошибка запуска
остаётся в отдельном серверном журнале. Сообщения и переходы выполняются
после успешного сохранения. Повтор одного запроса пользователя возвращает
сохранённый результат; другой пользователь не получает этот результат.

Миграция `0028_published_builder_runs` добавляет `app_action_runs` и
`app_workflow_runs` с привязкой к пользователю именно этого приложения.
История действий автора продолжает использовать свои таблицы.

## Оставшиеся границы

- Старые приложения не преобразуются и не публикуются автоматически.
- Удаление доступно отдельным подтверждённым действием автора; опубликованное
  удаление и цепочки `delete_row`, `go_back`, `open_url`, `copy_value` ещё не
  подключены. Публикация неподдерживаемой цепочки отклоняется целиком.
- События открытия экрана, действия внутри повторяющихся списков, условное
  скрытие полей формы и элементов внутри списка требуют следующих этапов.
  Публикация объясняет ограничение вместо молчаливого неполного исполнения.
- Журнал конечных пользователей сохраняется на сервере; его просмотр автором
  в общем интерфейсе ещё не подключён.
- Безопасное вычисление использует консервативное пересечение разрешённых
  полей связанных строк. При сложных разных правах поле может быть скрыто
  вместо частично рассчитанного результата.
- Корректность доступа проверена. Подсчёт и сортировка пока сканируют
  разрешённую выборку порциями; оптимизация больших таблиц остаётся в этапе 4.
- Неопределённый ответ сохраняет ключ повтора в открытой странице. Восстановление
  такого запроса после полной перезагрузки ещё не реализовано.
- Полный набор компонентов, оформление и дальнейшие шаги обучения остаются
  в плане. Этапы 4–7 целиком не объявляются завершёнными.

Дальше: интерфейс опубликованных запусков для автора и обучение сохранению,
доступу и публикации, затем оставшиеся события и компоненты по рабочему плану.
