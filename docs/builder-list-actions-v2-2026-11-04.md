# Кнопки внутри списков v2

Дата: 4 ноября 2026. Продолжение рабочего плана конструктора.

## Результат

В строку списка можно добавить кнопку и настроить её цепочку. Действие
получает ту запись, в которой нажали кнопку. Поддержаны обычный список,
карточки и табличный вид, в том числе кнопка внутри группы или колонок
одной строки списка. Размещение кнопки само по себе прав не выдаёт.

Для связанного списка на экране карточки строка и карточка являются разными
контекстами. Например, действие меняет задачу и создаёт запись журнала с
названием и связью проекта из открытой карточки. Настройки показывают
«Строка списка», «Открытая карточка» и связь с карточкой. Существующие цепочки
предлагаются только при совпадении контекстов.

В опубликованном приложении кнопка выполняется на месте. Проверка версии
и разрешений запрашивается по нажатию, без набора запросов для каждой строки.
Кнопки разных строк имеют отдельное состояние ожидания, ошибки и повтора.
Доступное имя кнопки включает название строки для работы со скринридером.

Обычное изменение, не сопровождаемое переходом или копированием, обновляет
список автоматически. Ушедшая из фильтра строка исчезает, сообщение об успехе
остаётся на странице, фокус переходит в тот же список. Переходы и копирование
сохраняют прежний порядок клиентских эффектов. Обновление вручную также
перечитывает источник, а не только серверную оболочку страницы.

В закрытом режиме автора предпросмотр открывает рабочую страницу конкретной
строки. Само открытие ничего не изменяет. Действие запускается отдельно на
этой странице. Кнопка «Открыть рабочее действие» в свойствах помогает выбрать
нужную строку в предпросмотре.

## Серверная проверка

Запрос содержит идентификатор экрана, кнопки, необязательный ID открытой
карточки и ID строки списка. Таблица, источник, тело действия и права берутся
из канонического определения приложения. Строка должна относиться к источнику,
быть доступна пользователю и подходить под текущий фильтр и представление.
Проверяются видимость кнопки и её родителей, условия и право запуска цепочки.
Вложенная форма или второй повторяемый контекст не принимаются.

В цепочку отдельно передаются текущая строка и родительская карточка.
Проверки, создание и изменение используют общий транзакционный движок.
Версии обеих записей и конфигурация представления защищают от устаревшего
запуска. Сам по себе пересчёт NOW в другом разрешённом поле не создаёт ложный
конфликт: при выполнении используются актуальные расчёты и повторно проверяются
условия списка.

Тот же ключ успешного запроса возвращает прежний результат после проверки
текущего доступа, даже если выполненное действие убрало строку из фильтра
или скрыло кнопку. Это не разрешает новое действие: новый запрос проходит
полную проверку списка. Подмена строки, родителя, пользователя, таблицы,
ключа или версии не обходит проверки.

Условия видимости повторяемых элементов остаются на сервере. Читатель списка
возвращает решения о видимых элементах для каждой разрешённой строки.
Клиент не получает тела условий, скрытые значения или тела изменяющих цепочек.
Подмена клиентского решения видимости не позволяет выполнить действие.

Авторский читатель использует ту же идентичность, включая организацию, что
и исполнитель. Условия по пользователю одинаковы при показе строки и запуске
кнопки. Курсор учитывает эту идентичность. Область чтения автора и отдельная
политика конечного пользователя при этом сохраняются.

## Проверки

- Полная регрессия: 256 файлов, 2 167 тестов, все пройдены. После уточнения
  выбора совместимых действий отдельно повторены 3 файла, 16 UI/публикационных
  проверок. Проверка типов проекта и скриптов пройдена.
- Итоговая production-сборка выполнена в изолированной копии исходников.
  Работающий dev-сервер и его `.next` не использовались для сборки.
- БД: конкретная строка списка; отдельный родитель карточки; связь с родителем
  и значение из него; чужая строка и неправильный родитель; фильтр источника;
  изменение фильтра сохранённого представления; версии; неизвестные поля
  запроса; ошибка видимости по скрытому полю; повтор после выхода строки из
  списка; NOW без ложного конфликта; одинаковый фильтр по организации автора.
- Интерфейс: список, карточки и таблица; отдельные состояния двух строк;
  отсутствие предварительных запросов на каждую строку; ID нужного элемента
  в запросе; серверные решения видимости; обновление источника; совместимые
  контексты в настройках; фокус при исчезновении строки.
- Браузер: автор выбрал кнопку внутри списка, увидел «Строка списка» в шаге
  изменения и открыл рабочее действие нужной строки. Отдельный app-user
  увидел две свои строки и не увидел чужую. Завершение первой строки на
  компьютере оставило одну строку; завершение второй на телефоне показало
  пустой список. Сообщение сохранилось без ручного обновления страницы.
- На viewport 320 px clientWidth/scrollWidth = 320/320. После выполнения
  фокус остался на области списка. Ошибок в консоли проверенной страницы нет.
- Уже открытое рабочее действие автора отказалось повторно менять строку,
  которая была завершена участником и больше не входила в список.

Проверочные данные: два успешных запуска опубликованного приложения, два
подтверждения результата и два изменения строк. Обе свои строки завершены;
чужая строка сохранилась без изменения. Устаревшая попытка автора не добавила
запуск или изменение. В пространстве был один участник, пользователь приложения
не получал членство в нём.

Временное пространство, аккаунт, приложение и тестовые сессии удалены с
проверкой точного имени и владельца. Вкладки закрыты, размер браузера
восстановлен. После очистки проверены 4 существующих приложения: 2 legacy-
и 3 v2-определения, отклонённых нет. Запись в реальные приложения не выполнялась.
Миграции не добавлялись, локальная история совпадает: 31 из 31.

## Дальше

Настраиваемые цепочки по нажатию на саму строку (itemPress). Сейчас это событие
по-прежнему открывает карточку. Вложенные списки, формы внутри строки и
удаление из повторяемого контекста не подключены. Расширенные компоненты,
оформление, автоматизации и общая приёмка остаются в рабочей матрице.
Этапы 4–7 целиком не объявляются завершёнными.
