# Клиенты салона

В новом шаблоне салона есть отдельная таблица «Клиенты», пункт меню и два
экрана: список и профиль. Администратор создаёт и редактирует имя, телефон,
почту и заметки через обычные формы конструктора. Клиент без визитов тоже
появляется в списке. Поиск работает по имени и контактам.

В таблице визитов добавлена постоянная связь с карточкой клиента. Имя и
контакты в старом визите остаются снимком на момент записи; история профиля
собирается по идентификатору клиента, поэтому переименование и смена контактов
её не теряют. Одинаковые имена/телефоны разных карточек не объединяют людей.

В административной форме записи можно выбрать существующего клиента или
«Новый клиент». Для выбранного клиента сервер берёт актуальные контакты из
его карточки; присланные подменённые значения не используются. «Записать
клиента» в профиле заранее выбирает его в форме.

Для нового клиента карточка и визит сохраняются в одной транзакции через
общий механизм строк: действуют лимиты, история изменений, уведомления и
откат. Повторный запрос не создаёт вторую карточку. Онлайн-запись использует
одну существующую карточку с совпадающей почтой, если совпадение однозначно;
иначе создаёт новую. По имени или телефону автоматического объединения нет.
Обычный клиент не может передать в форму произвольный идентификатор карточки.
Перенос и смена статуса сохраняют связь с клиентом.

Таблица контактов, личные заметки, экран клиентов и формы доступны только
администратору. Серверные чтения и запись дополнительно проверяют правила
строк и полей. Новый клиентский блок формы показывается только в форме
администратора с доступным полем связи.

Дополнительные настройки необязательны в схеме приложения. Уже установленные
приложения без новой таблицы работают в прежнем режиме с профилями из визитов.
Автоматическое переустройство их таблиц и перенос записей не выполнялись.
Новая структура есть в новых установках шаблона и публичном учебном примере.
В рабочую базу изменения не вносились; SQL-миграций продукту не требуется.

Проверены настоящий опубликованный путь форм, создание/изменение клиента,
сохранность связи после переименования, выбор клиента, защита от подмены,
повторный запрос и конкурирующие записи. PostgreSQL для тестов отдельная,
на порту 5547. В браузере пройден полный путь на учебных данных, список,
профиль и форма проверены на 1920, 1440, 768, 390 и 320 px.
Общий прогон: 117 тестов в 12 файлах, включая прежнюю запись и общие
контракты конструктора. Полная проверка типов прошла. В узком меню используются
короткие подписи «Записи» и «График»; заголовки экранов остаются полными.
