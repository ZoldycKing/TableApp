# TableApp

Совместные таблицы и конструктор приложений: импортируйте данные из CSV или Excel,
настройте представления и опубликуйте приложение для команды или клиентов.
Данные хранятся в PostgreSQL, вложения — в S3-совместимом хранилище.

Проект находится в разработке. Локальные проверки проходят, но публичное рабочее
окружение ещё не развёрнуто. Ограничения и следующие задачи —
в [плане развития](docs/roadmap.md).

## Возможности

- Таблица, канбан, календарь и галерея с фильтрами, сортировкой и поиском.
- Типизированные поля, формулы, связи между таблицами, Lookup и Rollup.
- Импорт CSV и многолистовых Excel-книг, экспорт данных.
- Конструктор экранов, карточек и форм; публикация приложения по ссылке.
- [Складской учёт](docs/inventory.md): приёмка, выдача, списания, возвраты, инвентаризация владельца и единый журнал движений.
- [Заявки и выезды](docs/templates.md#роли-в-заявках-и-выездах): диспетчер назначает работу, мастер видит свои заявки и меняет статус, фото и комментарий.
- Рабочие пространства, приглашения, роли и доступ к строкам и полям.
- Вход по почте, двухфакторная аутентификация, журнал изменений.
- Загрузка файлов, живые обновления через SSE, учёт использования и тарифов.
- Интерактивные примеры шаблонов на учебных данных открываются на `/templates`. Старые адреса `/demo` и `/demo/modular` перенаправляют туда.
- Модульное приложение: запись на услуги, продажи, ремонт, доставка, выезды, недвижимость и внутренние инструменты могут работать по одной ссылке с отдельными правилами и правами. Продажи связаны со складским резервом и выдачей; производство использует общий каталог готовой продукции и отдельные материалы.
- [Заказ → доставка](docs/order-delivery-2026-10-13.md): передача заказа в задание курьеру, фиксированные контакты и состав, согласованные статусы и отмена, защита от повторного создания в новых модульных наборах.
- [Переписка и документы по обращениям](docs/modular-conversations-2026-10-12.md): включение через черновик, сообщения клиента и сотрудников, отдельные внутренние заметки, защищённые вложения и история правок. [Общий раздел «Сообщения»](docs/business-messages-2026-10-13.md) объединяет доступные диалоги бизнеса, показывает непрочитанные ответы и позволяет открыть связанное обращение. Клиентский кабинет содержит такой же раздел со своими диалогами.
- История публикаций и изменений возможностей с проверкой восстановления в черновик. В клиентском пилоте история записей и заказов загружается при открытии раздела.
- Каталог стартовых наборов по задаче: шесть клиентских сценариев и три внутренних инструмента. «Продажа товаров» объединяет каталог и заказы; кабинет включён в клиентские сценарии. Старые определения и опубликованные приложения сохраняются. В ветке кабинета доступны [пошаговая подготовка, предпросмотр по ролям и база знаний](docs/guided-owner-ux-2026-10-20.md); отраслевые правила используют прежние модули.

## Технологии

TypeScript, Next.js 16 (App Router), React 19, Tailwind CSS 4, PostgreSQL 17,
Drizzle ORM, MinIO / S3, Vitest. Монорепозиторий управляется pnpm.
Точные версии зависимостей зафиксированы в `pnpm-lock.yaml`.

Анимации используют CSS и встроенный View Transition API: раскрытие карточки в
примере на главной, смена размера демо, появление секций при прокрутке и короткие
переходы экранов. Дополнительных библиотек нет. Без View Transition API интерфейс
продолжает работать; `prefers-reduced-motion` отключает движение, а автоматические
демонстрации останавливаются вне экрана и в скрытой вкладке. Шрифты и тексты
приложения от анимаций не зависят.
Пример на главной один раз превращает таблицу в каталог и экран телефона,
затем оставляет интерактивную витрину. Товар можно открыть на любой стадии;
это останавливает автопоказ. После возврата каталог остаётся на месте, показ
можно приостановить или повторить. Демонстрации общей цены на `/features` и
канбана на `/solutions/order-management` также проходят один цикл и оставляют
результат; ручной выбор сцены останавливает автопоказ. Ручной выбор главы
останавливает её автопереключение. Переходы рабочих
экранов занимают 220 мс и сохраняют введённые данные.

Страница `/motion-lab` содержит пять вариантов для просмотра: таблица → каталог →
телефон, общая правка цены, движение заявки по канбану, экраны разных ролей и
приёмка с телефона. Выбранный вариант повторяется автоматически; доступны пауза,
повтор и выбор отдельной сцены. Страница использует только тестовые данные,
не меняет записи в базе и закрыта от индексации. Под каждым вариантом указано
предлагаемое место на сайте; основной дизайн сайта остаётся прежним.

## Локальный запуск

Нужны Node.js **24.14.1**, pnpm **10.33.0** и Docker с Docker Compose.
Команды выполняются из корня репозитория.

```sh
pnpm install --frozen-lockfile
```

Создайте локальный файл настроек. В PowerShell:

```powershell
Copy-Item .env.example .env
```

В Bash:

```sh
cp .env.example .env
```

Затем запустите сервисы, примените миграции и запустите приложение:

```sh
pnpm db:up
pnpm db:migrate
pnpm --filter @tableapp/web dev
```

| Адрес | Назначение |
| --- | --- |
| http://localhost:3000 | Приложение |
| http://localhost:3000/demo | Демо без регистрации и заполнения базы |
| http://localhost:8025 | Mailpit: письма для локального входа |
| http://localhost:9001 | Консоль MinIO |
| localhost:5433 | PostgreSQL |

Значения в `.env.example` и Docker Compose предназначены для локальной разработки.
MinIO [собирается из закреплённого релиза исходников](infra/minio/README.md);
первая сборка контейнера может занять несколько минут.
Для обычной работы откройте `/login` и получите письмо в Mailpit.
Приложение читает корневой `.env`; этот файл не попадает в Git.

Необязательные примеры для отдельной тестовой базы можно создать командами `pnpm db:seed`,
`pnpm db:seed:relations`, `pnpm db:seed:owner` и `pnpm db:seed:photo`, в указанном
порядке. Они добавляют синтетические данные в базу и не требуются для `/demo`.
Для этих команд также задайте `DATABASE_URL` в окружении терминала (пример ниже).

## Проверки и сборка

```sh
pnpm typecheck
pnpm test
pnpm db:migrate:verify
```

Тесты с PostgreSQL требуют `DATABASE_URL`; без него эти проверки пропускаются.
Для полного локального набора задайте переменную из `.env` в окружении терминала:

```powershell
$env:DATABASE_URL = 'postgres://tableapp:tableapp@localhost:5433/tableapp'
pnpm test
```

Для сборки задайте `SITE_URL` с публичным адресом будущего развёртывания в `.env`
или окружении терминала, затем выполните `pnpm build`. Локальный адрес в рабочей
сборке отклоняется. `https://tableapp.example` подходит для проверки сборки;
при развёртывании замените его настоящим доменом.

GitHub Actions проверяет типы, тесты, миграции, сборку, HTTP-сценарии с PostgreSQL
и MinIO и восстановление резервной копии. Конфигурация —
[`.github/workflows/ci.yml`](.github/workflows/ci.yml).

## Структура

```text
apps/web/          интерфейс, серверные действия, API и рантайм приложений
packages/schema/   типы и правила полей, представлений, фильтров и доступа
packages/formula/  парсер и вычислитель формул и производных значений
packages/import/   разбор CSV и Excel, определение типов
packages/db/       схема PostgreSQL, версионные миграции и тестовые данные
scripts/           резервное копирование и проверки запуска
infra/minio/       сборка MinIO для разработки и CI
docs/              архитектура, эксплуатация и план развития
```

Поля адресуются по стабильным идентификаторам: переименование не меняет ключи
данных. Представления и правила фильтрации используются и редактором таблиц,
и опубликованными приложениями. Сервер проверяет доступ при чтении и записи.
