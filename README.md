# TableApp

Совместные таблицы и конструктор приложений: импортируйте данные из CSV или Excel,
настройте представления и опубликуйте приложение для команды или клиентов.
Данные хранятся в PostgreSQL, вложения — в S3-совместимом хранилище.

Проект находится в разработке. Локальные проверки проходят, но публичное рабочее
окружение ещё не развёрнуто. Ограничения и следующие задачи —
в [плане развития](docs/roadmap.md).

## Возможности

- Таблица, канбан, календарь и галерея с фильтрами, сортировкой и поиском.
- Типизированные поля, формулы, связи между таблицами, Lookup и Rollup.
- Импорт CSV и многолистовых Excel-книг, экспорт данных.
- Конструктор экранов, карточек и форм; публикация приложения по ссылке.
- Рабочие пространства, приглашения, роли и доступ к строкам и полям.
- Вход по почте, двухфакторная аутентификация, журнал изменений.
- Загрузка файлов, живые обновления через SSE, учёт использования и тарифов.
- Изолированное демо с синтетическими данными по адресу `/demo`.

## Технологии

TypeScript, Next.js 16 (App Router), React 19, Tailwind CSS 4, PostgreSQL 17,
Drizzle ORM, MinIO / S3, Vitest. Монорепозиторий управляется pnpm.
Точные версии зависимостей зафиксированы в `pnpm-lock.yaml`.

## Локальный запуск

Нужны Node.js **24.14.1**, pnpm **10.33.0** и Docker с Docker Compose.
Команды выполняются из корня репозитория.

```sh
pnpm install --frozen-lockfile
```

Создайте локальный файл настроек. В PowerShell:

```powershell
Copy-Item .env.example .env
```

В Bash:

```sh
cp .env.example .env
```

Затем запустите сервисы, примените миграции и запустите приложение:

```sh
pnpm db:up
pnpm db:migrate
pnpm --filter @tableapp/web dev
```

| Адрес | Назначение |
| --- | --- |
| http://localhost:3000 | Приложение |
| http://localhost:3000/demo | Демо без регистрации и заполнения базы |
| http://localhost:8025 | Mailpit: письма для локального входа |
| http://localhost:9001 | Консоль MinIO |
| localhost:5433 | PostgreSQL |

Значения в `.env.example` и Docker Compose предназначены для локальной разработки.
MinIO [собирается из закреплённого релиза исходников](infra/minio/README.md);
первая сборка контейнера может занять несколько минут.
Для обычной работы откройте `/login` и получите письмо в Mailpit.
Приложение читает корневой `.env`; этот файл не попадает в Git.

Необязательные примеры для отдельной тестовой базы можно создать командами `pnpm db:seed`,
`pnpm db:seed:relations`, `pnpm db:seed:owner` и `pnpm db:seed:photo`, в указанном
порядке. Они добавляют синтетические данные в базу и не требуются для `/demo`.
Для этих команд также задайте `DATABASE_URL` в окружении терминала (пример ниже).

## Проверки и сборка

```sh
pnpm typecheck
pnpm test
pnpm db:migrate:verify
```

Тесты с PostgreSQL требуют `DATABASE_URL`; без него эти проверки пропускаются.
Для полного локального набора задайте переменную из `.env` в окружении терминала:

```powershell
$env:DATABASE_URL = 'postgres://tableapp:tableapp@localhost:5433/tableapp'
pnpm test
```

Для сборки задайте `SITE_URL` с публичным адресом будущего развёртывания в `.env`
или окружении терминала, затем выполните `pnpm build`. Локальный адрес в рабочей
сборке отклоняется. `https://tableapp.example` подходит для проверки сборки;
при развёртывании замените его настоящим доменом.

GitHub Actions проверяет типы, тесты, миграции, сборку, HTTP-сценарии с PostgreSQL
и MinIO и восстановление резервной копии. Конфигурация —
[`.github/workflows/ci.yml`](.github/workflows/ci.yml).

## Структура

```text
apps/web/          интерфейс, серверные действия, API и рантайм приложений
packages/schema/   типы и правила полей, представлений, фильтров и доступа
packages/formula/  парсер и вычислитель формул и производных значений
packages/import/   разбор CSV и Excel, определение типов
packages/db/       схема PostgreSQL, версионные миграции и тестовые данные
scripts/           резервное копирование и проверки запуска
infra/minio/       сборка MinIO для разработки и CI
docs/              архитектура, эксплуатация и план развития
```

Поля адресуются по стабильным идентификаторам: переименование не меняет ключи
данных. Представления и правила фильтрации используются и редактором таблиц,
и опубликованными приложениями. Сервер проверяет доступ при чтении и записи.
