# Склад и приёмки

Шаблон «Склад и остатки» создаёт таблицы «Позиции» и «Приёмки» и готовое приложение.

Кладовщик видит товары, артикулы, фотографии и текущие остатки. Из карточки он открывает «Принять товар» и вводит целое положительное количество; комментарий необязателен. Цены, стоимость запаса, начальные остатки и формы редактирования товаров доступны владельцу.

Остаток — вычисляемое поле: начальный остаток плюс сумма связанных приёмок. Сервер записывает количество, товар, время и почту сотрудника. Приёмка и обратная связь с товаром сохраняются в одной транзакции. Повтор одного запроса не создаёт дубль; параллельные приёмки складываются. Журнал нельзя изменять через обычные действия опубликованного приложения. Владелец рабочего пространства может исправлять данные в редакторе таблиц.

Опубликованные приложения получают уведомления об изменении своих таблиц и перечитывают данные с проверкой прав. Обновления ждут завершения несохранённого ввода. Подписка охватывает связанные таблицы, нужные для вычисления остатков; содержимое строк по каналу уведомлений не передаётся. Канал работает в пределах одного процесса сервера, как существующий канал редактора таблиц. Для нескольких реплик понадобится общий транспорт событий.

## Подключение к старому складу

Откройте приложение старого шаблона в конструкторе и нажмите «Подключить приёмку». Существующее числовое поле «Остаток» станет «Начальным остатком» с тем же идентификатором и значениями. Будут добавлены журнал, связь, сумма приёмок, вычисляемый остаток и экраны. Строки товаров и их история сохраняются. Идентификаторы прежних ролей сохраняются: роль `client`, если она была, получает возможности кладовщика. Нестандартные роли, дополнительные экраны и изменённая структура автоматически не обновляются.

Изменения сценария сохраняются в черновик. Проверьте роли, список доступа и предпросмотр, затем опубликуйте приложение. Переустановка шаблона для этого не нужна. При отказе по лимиту таблиц вся настройка откатывается.

## Границы сценария

Реализована приёмка поступлений. Списания, отгрузки, складские документы расхода, штрихкоды и обмен с 1С в этот сценарий не входят. Производственный учёт сохраняет собственные движения материалов при выпуске продукции.

Конфигурация хранится в JSON определения приложения; миграция схемы PostgreSQL не требуется. Новые приложения получают сценарий при установке складского шаблона. Существующие приложения подключают его через конструктор.
