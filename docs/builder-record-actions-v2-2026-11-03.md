# Изменение и удаление записей v2

Дата: 3 ноября 2026 года. Продолжение этапа 5 после создания из формы.

## Что работает

- В карточке записи форма переключается на «Изменяет открытую запись».
  «После отправки → Сохранить изменения записи» подключает одиночный
  `update_row`. Открытая рабочая форма подставляет текущие значения.
  После сохранения можно открыть карточку или изменить запись ещё раз.
- Кнопке карточки назначается «Удалить открытую запись». Автор выбирает роли
  и открывает отдельное рабочее действие. Удаление показывает название записи
  в подтверждении; отмена возвращает фокус и ничего не записывает.
- Существующие создание из формы и проверка без записи сохранены. Встроенный
  и отдельный предпросмотр не исполняют записывающие действия.

Все рабочие операции пока предназначены для полных редакторов пространства,
дополнительно проверяются роли и политика приложения. Это не включение нового
опубликованного runtime для сотрудников и клиентов.

## Проверки и ограничения

Общий серверный загрузчик берёт сохранённый черновик, проверяет пространство,
экран, путь к компоненту и текущую роль. Действия внутри повторяемого списка,
формы внутри списка и условная видимость рабочих компонентов пока отклоняются.
Принимается весь одиночный workflow, а не первый шаг произвольной цепочки.

Изменение разрешено только для открытой записи таблицы формы. Клиент не передаёт
её доверенные значения или личность. Текущая строка блокируется, сервер повторно
проверяет строковые ограничения и поля. Закрытые поля не входят в patch,
а отсутствующие в форме значения сохраняются. Отпечаток формы учитывает версию
строки и конфигурацию; устаревшие данные не перезаписываются. Если конфигурация
страницы расходится с сохранённой формой, требуется обновление всей страницы.

Явное подключение действия добавляет только нужную операцию и поля. Имеющийся
`owned` scope для роли сохраняется; если права на изменение или удаление ещё
не заданы, используется ограничение владельца из чтения или создания. Поле
владельца нельзя включить в редактируемые поля такого правила. Размещение
компонента ничего не разрешает. Независимые права таблицы сохраняются при
отключении события. Общий интерфейс политики и чтение по правам конечного
пользователя ещё впереди; авторское чтение использует полные права пространства.

Удаление требует `confirm: true` в сохранённом действии и `confirmed: true`
в запросе. Подтверждение содержит показанную версию строки. Зависимые строки
старых предметных каскадов не удаляются незаметно: общая кнопка отказывает
и направляет к соответствующему разделу учёта. Для read-only проверки зависимости
читаются без блокировки; стандартные записывающие вызовы каскада сохранили
прежнее поведение по умолчанию.

Изменение и удаление используют общее ядро строк, предметные ограничения,
историю, счётчики и уведомления после фиксации. Удаление сохраняет существующую
модель мягкого удаления. Запись и результат запроса фиксируются одной транзакцией
в уже добавленной `builder_action_runs`; новая миграция не нужна. Конкурирующий
повтор не повторяет изменение, историю или удаление. Собственный результат
повтора доступен и после удаления строки при всё ещё разрешённом действии.
Подмена payload с прежним ключом отклоняется.

При потере ответа интерфейс удерживает исходный ключ и значения, блокирует
редактирование и предлагает повтор. Последующий отказ не сбрасывает неизвестный
результат предыдущей попытки. Для удаления в этом состоянии закрытие подтверждения
также заблокировано. Восстановление попытки после полной перезагрузки страницы
пока не реализовано. Опубликованное исполнение, составные действия, другие
события кнопки и следующие шаги обучения остаются в плане.

## Проверено

- Общий прогон: 240 файлов, 2073 теста; после правки подписи и переноса текста
  повторно прошли 16 профильных тестов интерфейса и настройки действий.
- DB: изменение той же строки, сохранность закрытых полей, 0 и false, исходные
  значения, чужая строка и пространство, смена роли и прав, отключённый rollout,
  подмена полей и личности, устаревшие строка и приложение, два одновременных
  запроса, одна история, повтор после удаления, обязательное подтверждение,
  отказ длинной цепочке и предметному каскаду без побочных удалений.
- Клиент: отмена и возврат фокуса, отдельное подтверждение, блокировка повторного
  нажатия, потеря ответа и тот же ключ, обновление устаревшей записи с повторным
  подтверждением, отображение результата, открытие карточки и новое редактирование.
- Типы всех пакетов и скриптов; production-сборка в отдельном каталоге,
  без использования `.next` работающего dev-сервера.
- Браузер: временное пространство с тремя проектами; настройка обоих действий
  через свойства, сохранение на компьютере и телефоне, проверка карточки,
  отмена, подтверждение и переход к списку. Ширины 390 и 320 px без переполнения.

История браузерной проверки: ровно два изменения и одно удаление, три результата
запроса. Число строк осталось 3, активных после удаления 2. Временные аккаунт
и пространство удалены по точной принадлежности. Проверка четырёх существующих
приложений после очистки: определения совместимы, записей в них не выполнялось.
