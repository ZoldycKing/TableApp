# Данные в конструкторе v2 — 1 ноября 2026

Выполнена первая часть этапа 4: чтение внутренних таблиц в новом редакторе
и отдельном защищённом предпросмотре. Это продолжение
[серверного редактора](builder-editor-v2-2026-11-01.md), а не завершение всего
этапа данных или включение публикации нового формата.

## Результат для автора

- Коллекции показывают реальные записи в виде списка, карточек или таблицы.
  На одном экране могут быть элементы из разных внутренних таблиц.
- Поиск применяется ко всему источнику, учитывает отображаемые названия
  вариантов выбора и связей, не зависит от регистра русского текста.
- У каждого блока свои условия, сортировка, поле поиска, размер страницы
  и необязательное представление. Отбор представления и блока объединяется;
  явная сортировка блока заменяет сортировку представления.
- Дублирование блока не связывает дальнейшие изменения его условий
  с оригиналом. Прежние определения с общим источником также разделяются
  при первой правке настроек одного блока.
- Настройки разделены на вкладки «Элемент» и «Данные». Условия вводятся
  через выбор поля, сравнения и значения, варианты выбора показаны по именам.
- Список загружается порциями от 1 до 100 записей; в интерфейсе предложены
  10, 30, 50 и 100. «Показать ещё» добавляет следующую страницу.
- Количество, сумма, среднее, минимум и максимум считаются на сервере по
  всему отобранному набору, а не по загруженной странице.
- Используются существующие формулы, системные поля, Lookup, Rollup и
  подписи связей. Вычисляемые значения не записываются обратно в таблицы.
- Вычисляются только необходимые зависимости. Посторонняя циклическая
  формула не ломает обычный список; ошибка в используемой формуле показывается
  с её названием и предложением проверить формулу.
- Изменение поиска или источника заменяет набор. Запоздавший ответ старого
  запроса не может подменить результат. Ошибку загрузки можно повторить;
  при устаревшем продолжении предлагается обновить список.

## Доступ и границы

Пока это **чтение автором по правам рабочего пространства**. Сервер повторно
проверяет действующую сессию, полный доступ к пространству, приложение,
принадлежность таблиц, полей и представлений. Участник с просмотром всего
пространства может читать данные, участник с доступом только к отдельным
таблицам не получает этот редакторский endpoint. Роль и личность из аргументов
браузера не принимаются.

Публикация v2, загрузка данных клиентами/сотрудниками по политике приложения,
выбор конкретной записи для карточки, начальные значения и сохранение форм
ещё не подключены. Правила `app.policy` не меняются при добавлении источника
или настройке списка. Нельзя использовать авторский reader как публичный
runtime: для него потребуется отдельная проверка опубликованного определения,
ролей приложения и разрешённых строк/полей. Интерфейс просмотра обозначает,
что показывает данные по правам вошедшего участника пространства.

Визуальный редактор условий поддерживает простые сравнения и плоские группы
«все/любое». Более сложное корректное условие сохраняется и исполняется;
его структура не упрощается молча. Группировка коллекций остаётся впереди.
Расчёты по связям используют существующую ограниченную модель вычислений ядра;
новый произвольный рекурсивный граф связанных расчётов не добавлялся.

## Как загружаются записи

Обычный список без отбора, поиска и сортировки читает ограниченную SQL-страницу.
Простой показатель количества считается SQL-запросом без загрузки строк.
Сложный отбор, сортировка, поиск и остальные показатели используют последовательные
серверные порции по 200 кандидатов. Для страницы удерживаются только лучшие
`pageSize + 1` записи; клиент получает лишь нужные отображаемые поля.
Это ограничивает память и ответ, но не означает, что сложный поиск по большой
таблице уже оптимизирован SQL-индексами. Замеры больших наборов остаются впереди.

Связанные записи читаются по конкретным идентификаторам в пределах того же
пространства. Чужой или удалённый идентификатор не раскрывает подпись и не
попадает в возвращённое значение связи. Запрос выполняется в read-only
транзакции с repeatable read. Курсор зашифрован и связан с автором, источником,
запросом, метаданными и ревизией данных. Изменившийся набор нельзя продолжить
старым курсором. Формулы на страницах используют один момент времени.

## Проверки

- Полная регрессия: **223 файла, 1992 теста**, все прошли.
- Целевая проверка: **28 тестов** графа, сохранения, отображения, загрузки
  и работы с БД. Проверены глобальная сортировка до разбиения на страницы,
  формулы и связи, вычисление по полному набору, подмена пространства,
  подделка/устаревание курсоров, отсутствие лишних полей и записей в БД,
  независимость источников и защита от запоздавших ответов.
- `pnpm typecheck`: все пакеты, web и служебные скрипты прошли.
- Отдельная production-сборка Next 16.3.5 прошла; `.next` работающего сервера
  на 3101 не использовалась для сборки.
- В отдельном браузерном аккаунте проверены 75 проектов и 3 задачи: загрузка
  30 → 60 строк, поиск русского текста, варианты выбора, два независимых
  списка, условие суммы больше 7000, порядок 75 → 71 и два источника на экране.
  Серверный итог формулы по всем 75 проектам — **570000**, при странице из 10 строк.
- Проверены 1440×1000, 390×844 и 320×780, отдельный просмотр и переключение
  вкладок свойств клавишей End. При 320 px ширина документа также 320 px.
  Это проверка размеров в Chrome, не физических телефонов.

Тестовый аккаунт и его данные удалены после проверки. Рабочие аккаунты для
изменения данных не использовались. Публичное окружение не разворачивалось.
После очистки проверено чтение сохранённых определений обоих форматов:
два прежних определения совместимы, два определения v2 читаются корректно;
проверка не выполняла записей.
