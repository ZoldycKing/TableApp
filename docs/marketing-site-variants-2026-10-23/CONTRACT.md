# Три полных варианта маркетингового сайта

Запрос: каждый вариант — весь маркетинговый сайт от навигации до футера, со всеми нужными страницами и контентом. Не повторять ограничение предыдущей итерации первыми экранами. Это три отдельные работающие локальные версии, без изменений продуктового кабинета и БД.

## Общий материал

`source-data.json`: канонические 9 шаблонов, 6 решений, 4 тарифа. `content.mjs`: общие короткие редакторские описания, сценарии, ограничения, шаги. Этот контент одинаков по фактам во всех вариантах. Никаких выдуманных достижений, клиентов, сроков запуска, уведомлений или оплаты.

Одинаковая существующая айдентика: Inter для текста, Unbounded для маркетинговых заголовков и TableApp, Literata italic для смыслового акцента. Цвета #fcfaf7, #25221d, #605b53, #365d40, #618769, #e8f0e4, #e8e2d8. Полные стили базовых элементов и рабочих миниатюр находятся в `base.css`; собственная композиция — в CSS варианта.

## Обязательные страницы каждого варианта (25)

- `/`, `/features`, `/how-it-works`, `/solutions`, `/templates`, `/pricing`, `/demo`.
- 6 `/solutions/<slug>` из данных.
- 9 `/templates/<id>` из данных.
- `/legal/privacy`, `/legal/terms`, `/legal/offer`: существующие тексты, без пересочинения правовых условий.

## API рендера

В `variants/<id>.mjs` экспортируются три функции:

```js
export function renderHeader(ctx) { return '...HTML...'; }
export function renderFooter(ctx) { return '...HTML...'; }
export function renderPage(ctx) { return '...содержимое main...'; }
```

`ctx` содержит:

- `variant`: tasks / product / world;
- `page`: `{type, path, title, item?}`; типы home, features, how, solutions, solution, templates, template, pricing, demo, legal;
- `data`: исходные templates, solutions, plans;
- `content`: редакторский материал; объект с `templates`, `solutions`, `features`, `steps`, `faq`, `hero`, `limits`;
- `h('/templates/zakazy')`: адрес внутри текущего варианта `/full/<variant>/templates/zakazy/`;
- `start(id?)`: реальный вход на 3101 с сохранением выбранного шаблона. Сам по себе ничего не устанавливает;
- `asset(name)`: `/full/assets/<name>`;
- `esc(string)`: HTML escaping;
- `ui.icon(name)`: SVG currentColor; поддерживаются box, calendar, users, orders, arrow, check, play, search, menu, close, table, shield, upload, factory, truck, edit;
- `ui.brand(ctx)`: логотип-ссылка на главную этого варианта;
- `ui.demo(ctx, kind='orders', interactive=false)`: наглядный рабочий экран. kind orders / booking / stock / production / crm / service / delivery / property / requests / client. На `/demo` interactive=true;
- `ui.pricing(ctx, mode='cards')`: честные 4 тарифа; mode='rows' допустим;
- `ui.templateCards(ctx, items?)`: карточки всех/переданных шаблонов, с короткими описаниями и ссылками;
- `ui.templateBrowser(ctx)`: интерактивный каталог с поиском, группами и пустым результатом;
- `ui.cta(ctx, title?, text?)`: финальный призыв, одно основное действие;
- `ui.legal(ctx)`: полные исходные тексты документов;
- `ui.workflow(ctx, items?)`: три коротких шага;
- `ui.world(ctx)`: иллюстрация одного связанного мира (business-world.png).

Все функции UI уже включают свои необходимые классы, семантику, тексты и data-атрибуты. Не создавать копию логики этих компонентов. Общая клиентская логика находится в `client.mjs`: мобильное меню, диалоги, фильтры, демо и анимация.

## Общие правила разметки

Генератор добавляет `<main id="main">` и skip-link. Не добавляйте второй main. Внутри страницы ровно один h1, короткие осмысленные h2. Header/footer возвращаются отдельно и обязательны на каждой странице.

Навигация: простые ссылки «Решения», «Шаблоны», «Возможности», «Тарифы», второстепенное демо и «Войти». Мобильное меню: `<button class="menu-toggle" data-menu-toggle aria-expanded="false" aria-controls="site-menu">` с доступным названием; контейнер `<nav id="site-menu" class="site-menu" aria-label="Разделы сайта">`. Родитель реализует открытие/закрытие. Не вкладывать ссылки в ссылки/кнопки.

Для общих анимаций добавляйте `data-reveal` секциям. Из коробки содержимое видно без JavaScript и при reduced-motion. Не прятать весь контент базовым opacity:0.

Для ключевой scroll-driven истории можно использовать `.scroll-story` с внутренними `.story-stage` и `.story-visual`, а также `.story-beat[data-beat="0"/"1"/"2"]`. CSS и разметка варианта задают композицию, родитель подключает локальный GSAP ScrollTrigger, уважает reduced-motion и отключение скриптов. В третьем варианте пользователь явно выбрал анимацию на коде и иллюстрациях вместо платного видео.

Информация об ограничениях короткая и по делу: без подключённого склада заказ не резервирует товар, со складом резерв создаётся при подтверждении. Отправка в доставку выполняется менеджером явно, не автоматически. Уведомления и онлайн-оплата не обещаются. Бесплатный тариф доступен сейчас; платные цены ориентировочные, оплата не подключена. Клиент видит только свои обращения после входа по коду на почту. Импорт Excel/CSV — дополнительный путь, не обязательное условие.

Длина главной — примерно 5–7 осмысленных разделов, не десяток повторов. Страница решения: подходящая задача, рабочий результат, три действия, подходящий шаблон, важные ограничения, следующий шаг. Деталь шаблона: назначение, готовые возможности, что добавить самостоятельно, пример экрана, ограничения, начать. Не показывать число колонок и схемы таблиц в маркетинговом выборе.

## Разделение работ

- tasks: только `variants/tasks.mjs`, `variants/tasks.css`;
- product: только `variants/product.mjs`, `variants/product.css`;
- world: только `variants/world.mjs`, `variants/world.css`.

Общие файлы, контент, сборку, активы и проверки ведёт родитель. Каждый вариант должен иметь собственную композицию ВСЕХ семейств страниц, не одну и ту же структуру с другим цветом. Не применять новый логотип или менять принятую палитру. Не делать backend, формы настоящей регистрации, отправку писем или платежи. После появления базовых компонентов можно проверить импорт и генерацию; браузерные проверки выполняет родитель общей серией.
