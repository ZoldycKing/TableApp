# Карточки и связанные списки конструктора v2

Дата: 2 ноября 2026 года. Часть этапа 4 из
[плана реализации](no-code-builder-implementation.md).

## Что работает

В свойствах списка во вкладке «Элемент» есть «При нажатии»: можно выбрать карточку
этой таблицы или создать новую. Создание добавляет экран с главным полем и ещё
несколькими полями; разрешения приложения не расширяются. Поддерживаются списки,
карточки и табличный вид, в том числе собственный шаблон строки без вложенных кнопок.

В предпросмотре автора строка открывает выбранную запись. Внутри карточки можно
разместить другую коллекцию, например задачи папки. Когда у таблицы задач ровно
одно поле Relation, направленное к таблице папок, новый список получает условие
«Папка → Связано с открытой записью». Это условие видно и редактируется в «Данных».
При нескольких подходящих связях автор выбирает поле сам. Поиск и порции списка
применяются внутри открытой папки, показатели используют весь отобранный набор.

Путь проверен до карточки задачи и обратно. Адрес содержит `screen` и `row`;
после обновления открывается та же запись. Отдельный защищённый просмотр и ссылка
обратно в редактор сохраняют контекст. Есть состояния загрузки, отсутствующей записи,
ошибки и повторной загрузки. При смене записи запоздавший ответ не возвращает старые
данные. В редакторе без выбранной записи остаётся макет карточки.

## Контракты и границы

В v2 различаются `row` / `row_id` — кандидат коллекции, и `screen_row` /
`screen_row_id` — запись открытого экрана. У зависимого источника есть необязательный
`screenTableId`. Сравнение `includes` проверяет членство в массиве Relation;
валидатор проверяет совместимость таблиц, а не только форму значения. Необязательные
поля не добавляются при чтении существующих определений.

Чтение карточки и вложенного списка доступно проверенному автору с полным доступом
к пространству. Сервер проверяет приложение, актуальный каталог, принадлежность
элемента экрану и запись нужной таблице; затем читает её заново в read-only
repeatable-read транзакции. Подмена таблицы, значений, актёра или контекста из другого
пространства отклоняется. Ответ содержит только отображаемые поля и их подписи.
Вычисления и связи используют общий план зависимостей. Курсор списка связан также
с выбранной записью и ревизией её таблицы.

В авторском просмотре выполняется только полный workflow из одного `open_screen`
с текущей записью. Переход не вынимается из более длинной цепочки с изменениями
или проверками. Формы и записывающие кнопки по-прежнему отключены.

Это ещё не опубликованное приложение с политикой конечного пользователя.
Создание/переименование папок, создание задач, назначение создателя сервером и
подстановка типизированной Relation в форму остаются этапами 4–5. Изоляция личных
папок двух конечных пользователей будет проверена после подключения политики
приложения. Размещение списка само по себе не даёт доступ к данным.

## Проверки

- Полная регрессия: **226 файлов, 2003 теста** прошли. После браузерной правки
  навигации: **10 файлов, 82 целевых теста** прошли.
- Проверены разные контексты строки и экрана, неверная таблица связи, отсутствие
  контекста, точная загрузка карточки, чужие и удалённые записи, вычисляемое поле
  открытой записи в отборе, глобальный поиск, порции, перенос и устаревание курсора,
  ограниченный участник, отсутствие записей в таблицы из просмотра.
- Проверены создание/дублирование/удаление карточек, неизменность политики доступа,
  безопасные переходы, отсутствие вложенных кнопок, запоздавшие ответы и Back/Forward.
- `pnpm typecheck` прошёл для всех пакетов, web и служебных скриптов.
- Production-сборка прошла в отдельной копии исходников; `.next` сервера 3101
  не использовалась для сборки.
- В браузере через интерфейс: создать карточку папки → добавить связанную таблицу
  задач → создать карточку задачи → открыть папку → открыть задачу → вернуться.
  «Личное»: 32 задачи, загрузка 30 → 32, поиск задачи 32. «Работа»: другие 3 задачи.
  Проверены обновление страницы, отдельный просмотр и возврат в редактор.
- Проверены ширины 1440, 390 и 320 px, включая свойства редактора при 320 px.
  Горизонтальной прокрутки документа нет. Это размеры браузера, не физические устройства.

Созданные для браузерной проверки отдельный аккаунт и пространство удалены.
Рабочие аккаунты и опубликованные приложения не изменялись.
