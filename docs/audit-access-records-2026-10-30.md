# Карточки записей и настройка доступа

30 октября 2026 года. Закрыт блок 9–10 [аудита](full-service-audit-2026-10-28.md).

## Карточки

При открытии таблицы сервер один раз определяет подходящие панели по опубликованным
определениям приложений этого пространства. Клиент получает только четыре признака:
товары заказа, доступность товара, доставка и история клиента. Названия таблиц
и их происхождение из шаблона не используются для определения операций.

Обычная таблица, производственные материалы и журнал движений больше не монтируют
посторонние панели и не запускают их серверные чтения. В связанных продажах сохраняются
подтверждение, выдача, возврат и доступность товара. Для таблиц логистики остаётся
проверка ранее связанной доставки, даже если рабочая пара модулей была разъединена.

Эти признаки управляют только интерфейсом. Серверные действия по-прежнему проверяют
текущую запись, рабочее пространство, права и версию. Для просмотра и ограниченного
табличного доступа панели не включаются. Runtime приложения уже проверяет применимость
до их подключения; его правила не менялись.

## Доступ

- Поля ролей, почты, организаций и ограничений получили подписи. Названия кнопок
  удаления включают конкретную роль, человека или номер ограничения.
- Вместо отдельных кнопок «основная / по умолчанию» используется один выбор роли
  по умолчанию. Пояснение описывает вход человека, которого нет в списке.
- Убраны выражения «он никто» и «правило сужает». Ограничения описаны через почту,
  организацию, таблицу и выбранные роли. Уточнено, как сочетаются несколько ограничений.
- Для модульных приложений видны назначенные направления работы. Названия полей
  и удаления различают назначения одной почты в разных модулях.
- Использованы общие поля и кнопки кабинета: на телефоне поля имеют шрифт 16 px,
  основные элементы управления высотой 44 px. На широком экране роли располагаются
  в две колонки, общая ширина настроек ограничена.

Редактирование продолжает изменять черновик. Идентификаторы ролей, правила серверного
доступа, порядок публикации и существующие назначения автоматически не переписываются.

## Проверки

- **80 тестов в 8 файлах прошли**: применимость панелей, подключение только нужных
  компонентов, запрет панелей в режиме просмотра, редактирование доступа без потери
  соседних назначений, старые проверки операций и правил чтения.
- Общий `pnpm typecheck` прошёл для пакетов и скриптов.
- Изолированная production-сборка Next.js с Turbopack прошла после очистки только
  её собственного `.next`. Первые попытки останавливались при запуске дочернего
  CSS-процесса. Основной dev-сервер и его `.next` не заменялись.
- В браузере проверены настройки ролей на 320, 390, 768 px и обычной ширине.
  Переполнения нет; размеры полей и кнопок проверены по DOM.
- Карточка существующего материала проверена без редактирования на 320, 390 и 768 px.
  Посторонних панелей нет, сохранение не запускалось. Пустой список сотрудников
  и роли проверены в интерфейсе; заполненные назначения, ограничения и модульный
  вариант дополнительно покрыты компонентными тестами.

При первых запусках Vitest не находил преобразованные модули во временной папке
песочницы. Итоговый запуск использовал отдельную временную папку внутри проекта
и один worker. Ошибка тестового идентификатора CRM исправлена до зелёного запуска.
Полная регрессия, CI и испытание на физическом телефоне в этот блок не входят.
Существующие данные, черновики и опубликованные приложения не редактировались.
