# Первый этап конструктора: рабочий прототип

31 октября 2026 года. План и критерии:
[очередь реализации](no-code-builder-implementation.md).

Адрес в локальном режиме разработки: <http://127.0.0.1:3101/builder-lab>.
Страница помечена «Прототип», закрыта от индексации; обработчик возвращает
404 при `NODE_ENV=production`. Отдельная production-сборка этого маршрута
на этом этапе не запускалась.

## Что можно проверить

- Создать экран с собственным названием и иконкой; выбрать стартовый экран
  и показ в меню. Карточки заявок и задач по умолчанию открываются из списка.
- Добавить заголовок, текст, показатель, список, поля записи, кнопку, форму,
  разделитель или колонки. Выбирать элементы в дереве и прямо на экране.
- Выбрать таблицу для элемента; показать заявки и задачи на одной странице.
- Переставить элемент в пределах родительского блока, скопировать или удалить;
  отменить и повторить изменение конфигурации.
- Изменить шаги действия: проверка поля, изменение значения, создание записи,
  история, сообщение и переход. Настроить значение и порядок шагов.
- Открыть «Попробовать», выбрать заявку и выполнить действие, добавить заявку
  через форму, посмотреть результат в проверочных таблицах и истории.
- Сравнить владельца и сотрудника: сотруднику показываются назначенные Анне
  записи. Это иллюстрация поведения, а не серверная защита доступа.
- Обновить страницу: конфигурация и проверочные данные сохраняются в этом
  браузере. История отмены после обновления начинается заново.

## Проверено

| Проверка | Результат |
| --- | --- |
| Целевые автоматические тесты | 2 файла, 8 тестов прошли |
| Проверка типов веб-приложения | Прошла |
| Изменение заголовка, отмена и повтор в браузере | Прошли |
| Создание собственного пустого экрана и списка из второй таблицы | Прошло |
| Изменение значения шага действия через интерфейс | Новое значение применяется при следующем запуске |
| Заявка → карточка → изменение статуса → история | Прошло |
| Создание заявки через форму и обновление списка | Прошло |
| Задача → собственная карточка и действие | Прошло, заявки не меняются |
| Переключение сотрудника | Чужие записи исключаются из списка и показателей |
| Обновление страницы | Названия, добавленный экран, настройки и проверочные данные восстановились |
| Экран 1440 × 1000 | Визуально проверен редактор с тремя панелями |
| Экраны 390 × 844 и 320 × 780 | Панели переключаются; ширина документа совпадает с шириной окна |
| Клавиатура и окно создания | Escape закрывает окно, фокус возвращается на вызвавшую кнопку |
| Ошибка позднего шага и повтор запроса | Автоматические тесты подтверждают откат и отсутствие повторной записи истории |
| Ошибка действия формы | Автоматический тест подтверждает сохранение введённых значений для повторной попытки |

Браузер: тестовый Chrome через Playwright, без личного профиля. Проверка
при узком размере окна не заменяет физический телефон. После окончательного
обновления страницы ошибок выполнения не было; в режиме разработки остаются
предупреждения о неиспользованных предварительных загрузках общих ресурсов.
Во время поочерёдного редактирования файлов был временный сбой горячего
обновления; после завершения правки и перезагрузки он не воспроизводится.

Снимки локально: `output/playwright/builder-desktop.png` и
`output/playwright/builder-mobile.png`. Диагностика браузера и снимки исключены
из Git. Полная регрессия и сборка основного сервиса на этом этапе повторно
не запускались: его ядро, API и рабочий редактор не менялись.

## Границы результата

Это самостоятельная проверка интерфейса. В ней две синтетические таблицы с
фиксированными полями и браузерное исполнение действий. Хранилище имеет
отдельный ключ `tableapp.builder-prototype.v1`; серверные данные аккаунта
не читаются и не изменяются. Публикация рабочего приложения не имитируется.

Ещё не реализованы: произвольные внутренние таблицы, серверное сохранение и
исполнение, ветвления, настройка состава полей формы и карточки, перенос между
контейнерами, полная настройка ролей, оформление, календарь, канбан, диаграммы,
миграция старых приложений и фоновые сценарии. Они остаются в матрице этапов 2–10.
Проверка непустого поля в прототипе не заменяет будущий редактор условий.

Нельзя переносить эту браузерную модель в рабочее ядро как готовый контракт:
следующий этап вводит проверяемый формат, типизированные контексты, явную
политику доступа и совместимость с действующими приложениями. Рабочие данные,
формулы, складские и производственные операции сохраняют существующие правила.
